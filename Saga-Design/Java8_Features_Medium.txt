1. Lambda Expressions

Lambda expressions in Java 8 are a powerful feature introduced to enable functional programming.They allow you to express instances of single-method interfaces (functional interfaces) more succinctly by providing a clear and concise way to represent a method.

Syntax:

A lambda expression in Java 8 has the following general syntax:

(parameters) -> expression
or
(parameters) -> { statements }

Components of Lambda Expressions

Parameters: The input to the lambda function, enclosed in parentheses. If there is only one parameter, you can omit the parentheses.

Arrow Operator (->): Separates the parameter(s) from the body of the lambda.

Body: The code to execute, which can be a single expression or a block of statements.

A single expression doesn’t require braces, and its value is implicitly returned.

A block of statements requires braces ({}), and you must use the return keyword to return a value.

java
import java.util.Arrays;
import java.util.List;

public class LambdaExample {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("Alice", "Bob", "Charlie");

        // Using Lambda Expression
        names.forEach(name -> System.out.println(name));
    }
}

Using a Lambda with Parameters

Using a lambda expression to sort a list with a custom comparator:

java

List<String> list = Arrays.asList("apple", "banana", "cherry");
Collections.sort(list, (a, b) -> b.compareTo(a)); // Sort in reverse order
System.out.println(list);

Using a Lambda with Block Syntax
If the body contains multiple statements:

java
Comparator<Integer> comparator = (a, b) -> {
    System.out.println("Comparing " + a + " and " + b);
    return Integer.compare(a, b);
};

Advantages of Lambda Expressions:

Less Boilerplate Code: Reduces the verbosity of anonymous classes.

Improved Readability: Code becomes cleaner and easier to understand.

Supports Functional Programming: Facilitates declarative and functional styles of coding.

Enhanced API Usage: Works seamlessly with the Streams API.

2. Functional Interfaces:

A lambda expression can only be used where a functional interface is expected. A functional interface is an interface with a single abstract method (SAM). Examples include Runnable, Comparator, and custom ones annotated with @FunctionalInterface.

Using a lambda expression to implement the Runnable interface:


Runnable r = () -> System.out.println("Running with a lambda!");
new Thread(r).start();

Using Custom Functional Interface
Define a functional interface and use it with a lambda:

java
@FunctionalInterface
interface Calculator {
    int operate(int a, int b);
}

public class LambdaExample {
    public static void main(String[] args) {
        Calculator add = (a, b) -> a + b;
        Calculator multiply = (a, b) -> a * b;

        System.out.println("Addition: " + add.operate(5, 3)); // Outputs 8
        System.out.println("Multiplication: " + multiply.operate(5, 3)); // Outputs 15
    }
}

3. Stream API

The Stream API in Java 8 is a powerful feature introduced to process collections of data in a functional style. It provides a way to perform operations such as filtering, mapping, and reducing on data in a declarative manner. A Stream represents a sequence of elements from a source, such as a collection, array, or I/O channel, that can be processed in a pipeline of operations. These operations can be intermediate (e.g., filtering, mapping) or terminal (e.g., collecting results, printing).

Key characteristics of the Stream API:

Functional: Operates using functional-style programming, leveraging Lambda Expressions.

Lazy Execution: Streams are evaluated lazily, meaning operations are performed only when needed.

Parallelism: Streams can perform parallel operations easily, utilizing multiple threads for improved performance.

Non-interfering: Operations on the stream do not modify the source data.

Benefits of the Stream API

Improved Readability: The declarative style of coding makes operations like filtering, mapping, and reduction easier to understand.

Less Boilerplate Code: Stream API reduces the need for explicit loops and temporary data structures, resulting in concise and clean code.

Enhanced Performance with Parallel Streams: By using parallel streams, you can process large datasets faster by leveraging multi-core processors.

Composability: Multiple operations can be chained together, forming a pipeline for data processing.

Ease of Transformation: Easily transform data into different formats or structures using mapping and flat-mapping techniques.

Examples of Stream API Usage

Basic Stream Operations

java
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class StreamExample {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("John", "Jane", "Tom", "Alice", "John");

        // Filter names starting with "J" and collect them into a new list
        List<String> filteredNames = names.stream()
                                          .filter(name -> name.startsWith("J"))
                                          .collect(Collectors.toList());

        System.out.println(filteredNames); // Output: [John, Jane, John]
    }
}

Mapping Elements

Using Collectors for Grouping

java
import java.util.Arrays;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class StreamGroupingExample {
    public static void main(String[] args) {
        List<String> items = Arrays.asList("apple", "banana", "orange", "apple", "banana");

        Map<String, Long> itemCount = items.stream()

    }
}

4. Default Methods in Interfaces

Before Java 8, interfaces could only declare methods without providing any implementation. However, Default Methods were introduced in Java 8 to allow interfaces to have methods with default implementations. These methods are defined with the default keyword within the interface, providing flexibility while maintaining backward compatibility.

A default method in an interface:

Can have a method body (implementation).

Allows extending interfaces without breaking existing implementations.

Provides a mechanism to add new functionality to existing interfaces in a consistent way.

Benefits of Default Methods in Interfaces

Backward Compatibility: Default methods enable you to add new methods to existing interfaces without requiring all implementing classes to provide an implementation. This ensures backward compatibility with older versions of the code.

Code Reusability: Default methods allow interfaces to share common behavior across multiple implementing classes, reducing code duplication.

Enhanced Interfaces: Interfaces can now act as semi-abstract classes by including reusable code.

Functional Interface Support: Default methods complement functional programming by enabling enhanced functionality in interfaces like Iterable, Collection, and Stream.

Simplified Design: Developers can focus on implementing only the core functionality in implementing classes, while shared functionality resides in the interface.

Syntax and Examples of Default Methods

Defining a Default Method

java
interface Vehicle {
    // Abstract method
    void start();

    // Default method with implementation
    default void stop() {
        System.out.println("Vehicle stopped.");
    }
}

Using a Default Method

java
class Car implements Vehicle {
    @Override
    public void start() {
        System.out.println("Car started.");
    }
}

public class DefaultMethodExample {
    public static void main(String[] args) {
        Vehicle car = new Car();
        car.start(); // Calls the implemented method
        car.stop();  // Calls the default method
    }
}

Overriding a Default Method

Implementing classes can override default methods if a specific implementation is required.

java
class Bike implements Vehicle {
    @Override
    public void start() {
        System.out.println("Bike started.");
    }

    @Override
    public void stop() {
        System.out.println("Bike stopped quickly.");
    }
}

public class OverrideDefaultMethodExample {
    public static void main(String[] args) {
        Vehicle bike = new Bike();
        bike.start();
        bike.stop(); // Calls the overridden method
    }
}

Multiple Inheritance with Default Methods (Conflict Resolution)
If a class implements multiple interfaces with conflicting default methods, it must resolve the conflict by overriding the method.

java
interface Vehicle {
    default void honk() {
        System.out.println("Vehicle honking!");
    }
}

interface Airplane {
    default void honk() {
        System.out.println("Airplane honking!");
    }
}

class FlyingCar implements Vehicle, Airplane {
    @Override
    public void honk() {
        System.out.println("FlyingCar honking uniquely!");
    }
}

public class ConflictResolutionExample {
    public static void main(String[] args) {
        FlyingCar flyingCar = new FlyingCar();
        flyingCar.honk(); // Resolves the conflict by using its own implementation
    }
}

Use Cases of Default Methods

Enhancing Existing APIs: Java’s core library added default methods to many existing interfaces, such as Iterable, Collection, and List. For example:

forEach method in Iterable is a default method.

java
Iterable<String> items = List.of("A", "B", "C");
items.forEach(System.out::println); // Default method in Iterable

Multiple Interfaces with Common Behavior: Default methods can provide shared functionality across interfaces without requiring code duplication.

Simplifying Functional Interfaces: Default methods enable functional interfaces to have additional helper methods while maintaining their core functionality.

5. Method References

Method References are a shorthand notation introduced in Java 8 for referring to methods or constructors directly without executing them. They provide a more concise and readable way to write lambda expressions when the lambda is only calling an existing method. Method references are part of Java’s functional programming features and work with functional interfaces.

The syntax for a method reference is ClassName::methodName or object::methodName.

Benefits of Method References

Improved Readability: Method references simplify the code by eliminating boilerplate syntax found in lambda expressions.

Reusability: They allow existing methods to be reused as functional interface implementations.

Reduced Errors: By removing unnecessary lambda code, method references reduce the chances of mistakes and improve clarity.

Elegant Code: They enhance code aesthetics by replacing verbose lambda expressions with concise, meaningful references.

Types of Method References

Reference to a Static Method (ClassName::staticMethod)

Reference to an Instance Method of a Particular Object (instance::instanceMethod)

Reference to an Instance Method of an Arbitrary Object of a Particular Type (ClassName::instanceMethod)

Reference to a Constructor (ClassName::new)

Examples of Method References

Reference to a Static Method

java
import java.util.function.Consumer;

class MethodReferenceExample {
    public static void printMessage(String message) {
        System.out.println("Static Method: " + message);
    }

    public static void main(String[] args) {
        Consumer<String> consumer = MethodReferenceExample::printMessage;
        consumer.accept("Hello, World!");
    }
}
Reference to an Instance Method of a Particular Object

java
import java.util.function.Consumer;

class MethodReferenceExample {
    public void display(String message) {
        System.out.println("Instance Method: " + message);
    }

    public static void main(String[] args) {
        MethodReferenceExample example = new MethodReferenceExample();
        Consumer<String> consumer = example::display;
        consumer.accept("Hello, Instance!");
    }
}
Reference to an Instance Method of an Arbitrary Object of a Particular Type

java
import java.util.Arrays;
import java.util.List;

public class ArbitraryObjectMethodReference {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("Alice", "Bob", "Charlie");

        // Using method reference for String's instance method
        names.forEach(System.out::println);
    }
}
Reference to a Constructor

java
import java.util.function.Supplier;

class Person {
    private String name;

    public Person() {
        this.name = "Default Name";
    }

    @Override
    public String toString() {

public class ConstructorReferenceExample {
    public static void main(String[] args) {

6. Optional Class:

The Optional class in Java 8 is a container class introduced to represent a value that might or might not be present. It is a part of the java.util package and provides a way to avoid null pointer exceptions by explicitly handling the absence of a value.

Optional acts as a wrapper for an object that can either contain a non-null value or be empty. It provides methods to check, retrieve, or process the contained value without directly working with null values.

Benefits of the Optional Class

Avoids NullPointerExceptions: Reduces the likelihood of runtime exceptions by ensuring null checks are explicitly handled.

Improves Code Readability: Makes the intent clear by explicitly signaling the possibility of an absent value.

Encourages Functional Programming: Works well with Java 8’s functional constructs like streams and lambda expressions.

Reduces Boilerplate Code: Simplifies common patterns like checking for null values and returning defaults.

Makes APIs More Robust: Enables clear and explicit contracts in APIs about when values might be optional.

Key Methods of the Optional Class

of(value): Creates an Optional containing the specified non-null value.

ofNullable(value): Creates an Optional that can contain a value or be empty if the value is null.

empty(): Returns an empty Optional.

isPresent(): Returns true if the value is present, otherwise false.

ifPresent(Consumer): Executes a consumer if the value is present.

orElse(value): Returns the value if present; otherwise, returns a default value.

orElseGet(Supplier): Returns the value if present; otherwise, invokes a supplier to provide a value.

orElseThrow(Supplier): Returns the value if present; otherwise, throws an exception.

map(Function): Applies a function to the value if present and returns a new Optional.

flatMap(Function): Similar to map, but avoids nesting of Optional.

filter(Predicate): Returns an Optional if the value satisfies the predicate.

Examples of the Optional Class

Creating an Optional

java
import java.util.Optional;

public class OptionalExample {
    public static void main(String[] args) {
        // Creating an Optional with a value
        Optional<String> optional = Optional.of("Hello, Optional!");
        System.out.println(optional.isPresent()); // Output: true
        System.out.println(optional.get());       // Output: Hello, Optional!

        // Creating an Optional with a null value
        Optional<String> optionalNullable = Optional.ofNullable(null);
        System.out.println(optionalNullable.isPresent()); // Output: false

        // Creating an empty Optional
        Optional<String> emptyOptional = Optional.empty();
        System.out.println(emptyOptional.isPresent());    // Output: false
    }
}

Avoiding Null Checks

java
import java.util.Optional;

public class AvoidNullChecksExample {
    public static void main(String[] args) {
        String value = null;

        // Using Optional to handle potential null value
        Optional<String> optionalValue = Optional.ofNullable(value);

        String result = optionalValue.orElse("Default Value");
        System.out.println(result); // Output: Default Value
    }
}

Using ifPresent


import java.util.Optional;

public class IfPresentExample {
    public static void main(String[] args) {
        Optional<String> optional = Optional.of("Hello, World!");

        // Perform an action only if the value is present
        optional.ifPresent(value -> System.out.println("Value is: " + value));
        // Output: Value is: Hello, World!
    }
}
Using map and flatMap


import java.util.Optional;

public class MapFlatMapExample {
    public static void main(String[] args) {
        Optional<String> optional = Optional.of("Hello");

        // Transforming the value using map
        Optional<String> uppercased = optional.map(String::toUpperCase);
        uppercased.ifPresent(System.out::println); // Output: HELLO

        // Transforming using flatMap (avoids nested Optional)
        Optional<Optional<String>> nestedOptional = optional.map(value -> Optional.of(value.toLowerCase()));
        System.out.println(nestedOptional); // Output: Optional[Optional[hello]]

        Optional<String> flatMapped = optional.flatMap(value -> Optional.of(value.toLowerCase()));
        System.out.println(flatMapped); // Output: Optional[hello]
    }
}

Throwing an Exception with orElseThrow

java
import java.util.Optional;

public class OrElseThrowExample {
    public static void main(String[] args) {
        Optional<String> optional = Optional.ofNullable(null);

        // Throw an exception if the value is not present
        String value = optional.orElseThrow(() -> new IllegalArgumentException("Value is not present"));
    }
}
Filtering Values

java
import java.util.Optional;

public class FilterExample {
    public static void main(String[] args) {
        Optional<String> optional = Optional.of("Optional Example");

        // Filter values that satisfy a condition
        optional.filter(value -> value.startsWith("Optional"))

    }
}
Use Cases of the Optional Class

Method Return Types: Instead of returning null, methods can return an Optional to indicate the possibility of an absent value.

    return id == 1 ? Optional.of("User1") : Optional.empty();
}
Chaining Operations: Optional allows chaining operations like map and filter to process data more elegantly.

Avoiding Explicit Null Checks: Code that previously relied on cumbersome null checks can now handle absence more declaratively with Optional.

7. Date and Time API

Java 8 introduced a modern Date and Time API in the java.time package to address the shortcomings of the previous java.util.Date and java.util.Calendar classes. The new API is inspired by the Joda-Time library and provides a comprehensive, robust, and user-friendly approach to handle date and time.

The key classes of the java.time package are:

LocalDate: Represents a date without time (e.g., 2024-12-03).

LocalTime: Represents a time without a date (e.g., 14:30:15).

LocalDateTime: Represents a combination of date and time without timezone.

ZonedDateTime: Represents a date-time with a timezone.

Instant: Represents a specific point on the timeline (typically used for timestamps).

Duration and Period: Represent time-based and date-based amounts, respectively.

DateTimeFormatter: Used for formatting and parsing dates and times.

Benefits of the Date and Time API in Java 8

Immutability: All classes in the new API are immutable and thread-safe, ensuring consistency and preventing unexpected behavior in concurrent environments.

Clearer API Design: The new API offers intuitive and clear methods for manipulating dates and times, avoiding the confusion of java.util.Date and java.util.Calendar.

Seamless Timezone Handling: The ZonedDateTime class simplifies handling of time zones.

Fluent API: Provides a fluent and chainable API for performing operations like adding, subtracting, or formatting dates and times.

Separation of Concerns: Different classes for date (LocalDate), time (LocalTime), and date-time (LocalDateTime) improve clarity.

Built-in Support for ISO Standards: Default formats align with ISO-8601 standards, reducing errors in date-time parsing.

Easy Conversion: Provides methods to convert between legacy and modern date-time classes.

Key Classes and Examples

LocalDate (Date without time)

java
import java.time.LocalDate;

public class LocalDateExample {
    public static void main(String[] args) {
        LocalDate today = LocalDate.now(); // Current date
        System.out.println("Today's date: " + today);

        LocalDate specificDate = LocalDate.of(2024, 12, 3);
        System.out.println("Specific date: " + specificDate);

        // Add days
        LocalDate nextWeek = today.plusDays(7);
        System.out.println("Next week's date: " + nextWeek);

        // Check if leap year
        System.out.println("Is 2024 a leap year? " + specificDate.isLeapYear());
    }
}

8. Nashorn JavaScript Engine
The Nashorn JavaScript Engine is a lightweight, high-performance JavaScript engine introduced in Java 8 as a replacement for the older Rhino engine. It is part of the javax.script package and is built to provide a more efficient and faster execution of JavaScript code within the Java Virtual Machine (JVM). Nashorn means "rhino" in German, symbolizing its predecessor, but it was developed to address the shortcomings of Rhino with better performance and modern features.

Nashorn is based on Java 7’s Project JSR-223 (Scripting for the Java Platform) and supports ECMAScript 5.1 and partial ECMAScript 6 features. It allows developers to run JavaScript code, embed JavaScript in Java applications, and even call Java code from JavaScript.

Key Features of Nashorn

Execution of JavaScript from Java: Nashorn allows Java applications to evaluate and execute JavaScript code.

ECMAScript 5.1 Compliance: It supports most ECMAScript 5.1 features, providing a modern JavaScript experience.

Improved Performance: Nashorn is designed for high performance, leveraging the invokedynamic feature of Java 7.

Tight Integration with Java: JavaScript code can interact seamlessly with Java objects and APIs.

Command-Line Tool (jjs): Nashorn comes with a command-line tool (jjs) for executing JavaScript files.

Benefits of Nashorn JavaScript Engine in Java 8

Improved Performance: Nashorn provides significant performance improvements over the older Rhino engine, which made JavaScript execution slower. It compiles JavaScript code to Java bytecode dynamically, enabling faster execution.

Compatibility with Modern JavaScript: Nashorn supports most of ECMAScript 5.1 features and parts of ECMAScript 6, which makes it more aligned with contemporary JavaScript standards compared to the older Rhino engine.

Interoperability with Java: Nashorn allows seamless interaction between Java and JavaScript. Java objects can be passed into JavaScript, and JavaScript can access Java classes, libraries, and methods.

Simplified Syntax: Nashorn comes with a simpler API for integration, compared to its predecessor, making it easier for developers to use within Java applications.

Access to Java APIs: JavaScript code executed in Nashorn can access Java APIs directly, enabling hybrid applications where Java and JavaScript components work together.

Lightweight: Nashorn is designed to be efficient and use fewer resources compared to other JavaScript engines.

Example of Using Nashorn JavaScript Engine in Java 8
To use Nashorn, developers typically use the ScriptEngineManager class provided by javax.script.

Example 1: Executing JavaScript Code from Java

java
import javax.script.ScriptEngine;
import javax.script.ScriptEngineManager;
import javax.script.ScriptException;

public class NashornExample {
    public static void main(String[] args) {
        // Create a ScriptEngineManager instance and get the Nashorn engine
        ScriptEngine engine = new ScriptEngineManager().getEngineByName("nashorn");

        // JavaScript code as a string
        String script = "var greeting = 'Hello, world!';" +
                        "var number = 42;" +
                        "greeting + ' The number is ' + number;";

        try {
            // Evaluate the script and print the result
            Object result = engine.eval(script);
            System.out.println("Result: " + result);
        } catch (ScriptException e) {
            e.printStackTrace();
        }
    }
}

11. Base64 Encoding and Decoding

Compatibility: Base64 encoding ensures that binary data can be safely transferred across systems that may only handle text-based data. This is especially useful for transferring data in HTTP requests, cookies, and other text-based formats.

14. Parallel Array Sorting

Parallel Array Sorting in Java 8 is an enhancement introduced to efficiently sort large arrays by leveraging multi-core processors. Prior to Java 8, array sorting was done sequentially, meaning only one core of the processor would be used to perform the sort operation. With Java 8, you can use the Arrays.parallelSort() method, which divides the array into smaller chunks and sorts them in parallel, leading to significant performance improvements, especially for large datasets.

How Parallel Sorting Works

The array is split into smaller subarrays.

Each subarray is sorted independently in parallel using multiple threads.

The sorted subarrays are merged to create a final sorted array.

The underlying implementation in Java 8 uses the ForkJoinPool, which is part of the java.util.concurrent package. The ForkJoinPool manages the parallel tasks efficiently and helps distribute the work among the available processor cores.

Benefits of Parallel Array Sorting in Java 8

Improved Performance for Large Datasets: Parallel sorting can significantly reduce sorting time for large arrays compared to sequential sorting, as it takes advantage of multi-core processors.

Simplified Code: The parallelSort() method simplifies parallel sorting without the need to manually create and manage threads.

Optimal Use of CPU Cores: By using parallel processing, Java 8 can efficiently utilize all available CPU cores, making better use of modern hardware.

Easy to Use: It requires only a single method call (Arrays.parallelSort()), reducing complexity and improving code readability.

3. StampedLock

StampedLock is a new locking mechanism introduced in Java 8. It is more scalable than traditional locks like ReentrantLock and provides three modes of locking:

Write Lock: Exclusive access.

Read Lock: Shared access for reading.

Optimistic Read Lock: A lightweight read lock that avoids blocking other threads unless necessary.

Example: Using StampedLock

java
import java.util.concurrent.locks.StampedLock;

public class StampedLockExample {
    private final StampedLock lock = new StampedLock();
    private int value;

    public void increment() {
        long stamp = lock.writeLock();
        try {
            value++;
        } finally {
            lock.unlockWrite(stamp);
        }
    }

    public int read() {
        long stamp = lock.tryOptimisticRead();
        int currentValue = value;
        if (!lock.validate(stamp)) { // Check if the value has changed
            stamp = lock.readLock();
            try {
                currentValue = value;
            } finally {
                lock.unlockRead(stamp);
            }
        }
        return currentValue;
    }
}


Benefits:

Improved performance: Optimistic reads minimize contention in read-heavy scenarios.

Fine-grained control: Developers can choose the appropriate locking mechanism for their use case.

Less contention: Reduces blocking compared to traditional locks.
