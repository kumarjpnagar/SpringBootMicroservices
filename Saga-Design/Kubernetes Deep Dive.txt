SECTION 1: Introduction to Kubernetes

1.1 What is Kubernetes?
Kubernetes (K8s) is an open-source container orchestration platform that automates the deployment, scaling, and management of containerized applications.

Historical Context:
Origins: Born from Google's internal project called Borg (used for over a decade to manage billions of containers)

Open Source Release: 2014

Current Steward: Cloud Native Computing Foundation (CNCF)

Language: Written in Go (Golang)

Why Kubernetes Matters:
text
Traditional Deployment → Container Deployment → Kubernetes Orchestration
   (Physical servers)    (Docker containers)    (Automated management)
1.2 Benefits of Kubernetes
A. Planet Scale
Designed on same principles that allow Google to run billions of containers weekly

Scales without increasing your operations team

Handles massive workloads with minimal overhead

B. Never Outgrow
Works from local testing to global enterprise

Flexibility to grow with your needs

Consistent experience regardless of complexity

C. Run Anywhere
Open source = freedom to use:

On-premises infrastructure

Hybrid cloud

Public cloud (AWS, GCP, Azure)

Effortlessly move workloads between environments

1.3 What Kubernetes Does For You
Core Capabilities:
Service Discovery & Load Balancing

Exposes containers using DNS or IP addresses

Load balances traffic across containers

Storage Orchestration

Automatically mounts storage systems of your choice

Automated Rollouts & Rollbacks

Gradually rolls out changes

Automatically rolls back if something goes wrong

Automatic Bin Packing

Places containers based on resource requirements

Optimizes resource utilization

Self-Healing

Restarts failed containers

Replaces and reschedules containers when nodes die

Kills containers that don't respond to health checks

Secret & Configuration Management

Manages sensitive information

Updates configuration without rebuilding images

Horizontal Scaling

Scales applications up/down based on CPU usage

Supports custom metrics for autoscaling

1.5 Common Use Cases
When to Use Kubernetes:
Microservices Architecture: Managing multiple independent services

CI/CD Pipelines: Automated deployment and rollback

Big Data Processing: Batch jobs and data pipelines

Machine Learning: Training and serving models

Multi-cloud Deployments: Hybrid cloud strategies

When NOT to Use Kubernetes:
Simple applications (single container)

Small teams with no DevOps expertise

Legacy monolithic applications (without containerization)

Short-lived projects

Kubernetes' backing store

Stores ALL cluster data (configuration, state, secrets)

Consistent and highly-available

Must be backed up regularly

Best Practices:

Use separate etcd cluster for HA

Regular backups

Encrypt sensitive data

SECTION 3: Key Concepts Deep Dive
3.1 Pods - The Atomic Unit
What is a Pod?
Smallest deployable unit in Kubernetes

Logical host for one or more containers

Single IP address shared by all containers

Shared storage volumes

Collaborative processes that work together

Pod Lifecycle:
text
┌──────────┐
│  Pending │  ← Pod accepted but containers not running
└────┬─────┘
     │
     ▼
┌──────────┐
│ Running  │  ← All containers running
└────┬─────┘
     │
     ▼
┌──────────┐
│Succeeded │  ← All containers terminated successfully
└──────────┘

OR

┌──────────┐
│ Running  │
└────┬─────┘
     │
     ▼
┌──────────┐
│  Failed  │  ← At least one container terminated with error
└──────────┘

OR

┌──────────┐
│  Pending │
└────┬─────┘
     │
     ▼
┌──────────┐
│  Unknown │  ← Pod state cannot be determined
└──────────┘
Pod Phases:
Pending: Pod accepted by system, containers not created

Running: Pod bound to node, all containers created

Succeeded: All containers terminated with success

Failed: At least one container terminated with failure

Unknown: Pod state unknown (typically node communication issue)

Example: Single-Container Pod
pod-single.yaml:

yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
  labels:
    app: myapp
    version: v1
spec:
  containers:
  - name: myapp-container
    image: nginx:1.19
    ports:
    - containerPort: 80
    env:
    - name: ENVIRONMENT
      value: "production"
    - name: DATABASE_URL
      value: "postgres://user:pass@db-service:5432/mydb"
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"
Example: Multi-Container Pod
pod-multi.yaml:

yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-app-pod
  labels:
    app: web-app
spec:
  volumes:
  - name: shared-data
    emptyDir: {}
  
  containers:
  # Main Application Container
  - name: nginx
    image: nginx:1.19
    volumeMounts:
    - name: shared-data
      mountPath: /usr/share/nginx/html
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
  
  # Sidecar Container (Updates files from remote)
  - name: content-updater
    image: busybox
    volumeMounts:
    - name: shared-data
      mountPath: /data
    command:
    - /bin/sh
    - -c
    - |
      while true; do
        wget -O /data/index.html https://example.com/content
        sleep 3600
      done
    resources:
      requests:
        memory: "32Mi"
        cpu: "100m"

3.2 Labels and Selectors

Common Label Patterns:

yaml

    environment: production       # Environment

Selectors: Querying Labels
Equality-Based Selectors:

yaml
selector:
  matchLabels:
    app: myapp
    environment: production
Set-Based Selectors:

yaml
selector:
  matchExpressions:
  - key: environment
    operator: In
    values:
    - production
    - staging
  - key: version
    operator: NotIn
    values:
    - v1.0.0
  - key: tier
    operator: Exists

4.2 Complete Deployment YAML Template
deployment-complete.yaml:

yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: microservice-name
  namespace: production
  labels:
    app: microservice-name
    environment: production
    version: v1.0.0
    team: backend
  annotations:
    description: "Complete microservice deployment"
    build-url: "https://jenkins/company/job/build/123"
    
spec:
  # Replica Count
  replicas: 3
  
  # Revision History
  revisionHistoryLimit: 10
  
  # Strategy
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  
  # Selector
  selector:
    matchLabels:
      app: microservice-name
  
  # Pod Template
  template:
    metadata:
      labels:
        app: microservice-name
        version: v1.0.0
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8080"
        
    spec:
      # Service Account
      serviceAccountName: microservice-sa
      
      # Security Context
      securityContext:
        runAsUser: 1000
        runAsGroup: 3000
        fsGroup: 2000
      
      # Init Containers
      initContainers:
      - name: init-db
        image: busybox:latest
        command: ['sh', '-c', 'echo "Checking database connection..."']
      
      # Main Containers
      containers:
      - name: microservice-container
        image: company/microservice:latest
        imagePullPolicy: Always
        
        # Ports
        ports:
        - containerPort: 8080
          name: http
          protocol: TCP
        - containerPort: 9090
          name: metrics
          protocol: TCP
        
        # Environment Variables
        env:
        - name: ENVIRONMENT
          valueFrom:
            configMapKeyRef:
              name: microservice-config
              key: environment
        - name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: microservice-secrets
              key: database-url
        - name: LOG_LEVEL
          value: "INFO"
        
        # Resources
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
        
        # Liveness Probe
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
          timeoutSeconds: 5
          failureThreshold: 3
        
        # Readiness Probe
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 20
          periodSeconds: 5
          timeoutSeconds: 3
          failureThreshold: 2
        
        # Volume Mounts
        volumeMounts:
        - name: config-volume
          mountPath: /app/config
          readOnly: true
        - name: data-volume
          mountPath: /app/data
          subPath: data
        
        # Pre-stop Hook
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 10"]
      
      # Volumes
      volumes:
      - name: config-volume
        configMap:
          name: microservice-config
      - name: data-volume
        persistentVolumeClaim:
          claimName: microservice-pvc
      
      # Node Affinity
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: node-type
                operator: In
                values:
                - general
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: app
                  operator: In
                  values:
                  - microservice-name
              topologyKey: kubernetes.io/hostname
      
      # Tolerations
      tolerations:
      - key: "key"
        operator: "Equal"
        value: "value"
        effect: "NoSchedule"
      
      # DNS Configuration
      dnsPolicy: ClusterFirst
      dnsConfig:
        options:
        - name: ndots
          value: "2"
      
      # Termination Grace Period
      terminationGracePeriodSeconds: 60

Complete Ubuntu Setup Script:
install-k8s.sh:

bash
#!/bin/bash
# Kubernetes Installation Script

# Update system
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl

# Install Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo systemctl enable docker
sudo systemctl start docker

# Add Kubernetes repository
curl -s https://packages.cloud.google.com/apt/doc/apt-key.gpg | sudo apt-key add -
echo "deb https://apt.kubernetes.io/ kubernetes-xenial main" | sudo tee /etc/apt/sources.list.d/kubernetes.list

# Install kubeadm, kubelet, kubectl
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

# Disable swap
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# Enable bridge traffic
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-ip6tables = 1
net.bridge.bridge-nf-call-iptables = 1
EOF
sudo sysctl --system

# Initialize cluster on master
if [ "$HOSTNAME" == "master" ]; then
    sudo kubeadm init --pod-network-cidr=10.244.0.0/16
    
    mkdir -p $HOME/.kube
    sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
    sudo chown $(id -u):$(id -g) $HOME/.kube/config
    
    # Install Flannel network
    kubectl apply -f https://raw.githubusercontent.com/coreos/flannel/master/Documentation/kube-flannel.yml
    
    echo "Master initialized successfully!"
    echo "Join command:"
    kubeadm token create --print-join-command
fi

Rollback Strategy:
rollback.sh:

bash
#!/bin/bash

SERVICE=$1
REVISION=$2

if [ -z "$SERVICE" ] || [ -z "$REVISION" ]; then
    echo "Usage: ./rollback.sh <service-name> <revision-number>"
    echo "Example: ./rollback.sh user-service 3"
    exit 1
fi

echo "🔄 Rolling back $SERVICE to revision $REVISION..."
kubectl rollout undo deployment/$SERVICE -n production --to-revision=$REVISION

echo "⏳ Waiting for rollback to complete..."
kubectl rollout status deployment/$SERVICE -n production

echo "✅ Rollback complete!"
