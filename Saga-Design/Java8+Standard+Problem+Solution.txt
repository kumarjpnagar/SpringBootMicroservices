import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class EvenOddNumbers {

    public static void main(String[] args) {

        // Step 1: Input list
        List<Integer> numbers = Arrays.asList(1, 2, 3, 4, 5, 6, 7, 8);

        // Step 2: Filter EVEN numbers
        List<Integer> even =
                numbers.stream()
                       // Condition: divisible by 2 → EVEN
                       .filter(n -> n % 2 == 0)
                       .collect(Collectors.toList());

        // Step 3: Filter ODD numbers
        List<Integer> odd =
                numbers.stream()
                       // Condition: NOT divisible by 2 → ODD
                       .filter(n -> n % 2 != 0)
                       .collect(Collectors.toList());

        // Step 4: Print results
        System.out.println("Even numbers: " + even);
        System.out.println("Odd numbers: " + odd);
    }
}

import java.util.Arrays;
import java.util.Comparator;
import java.util.Optional;

public class SecondHighestPrimitive {
    public static void main(String[] args) {
        int[] numbers = {5, 13, 99, 41, 88, 99, 77};

        Optional<Integer> secondHighest = Arrays.stream(numbers)
                .boxed() // Converts int to Integer wrapper objects
                .distinct() // Removes duplicate highest numbers
                .sorted(Comparator.reverseOrder()) // Sorts from highest to lowest
                .skip(1) // Skips the highest number
                .findFirst(); // Retrieves the next available number

        secondHighest.ifPresentOrElse(
            value -> System.out.println("Second highest number: " + value),
            () -> System.out.println("Array does not have a second highest number.")
        );
    }
}

Q9: Approach 2: Using Set (Best Practice):

import java.util.*;
import java.util.stream.*;

public class FindDuplicates {

    public static void main(String[] args) {

        List<Integer> list = Arrays.asList(1,2,3,2,4,5,1,6);

        // Step 1: Create a Set to track seen elements
        Set<Integer> seen = new HashSet<>();

        // Step 2: Find duplicates
        Set<Integer> duplicates =
                list.stream()

                    // Step 3:
                    // set.add(n) returns:
                    // TRUE  → if element is new
                    // FALSE → if element already exists (duplicate)
                    .filter(n -> !seen.add(n))

                    // Step 4: Collect duplicates
                    .collect(Collectors.toSet());

        // Step 5: Print result
        System.out.println(duplicates);
    }
}

        List<String> list = Arrays.asList("AABCC");

            // Split each string into an array of characters, then map to stream

            .mapToObj(c -> String.valueOf((char) c))
            // Collect into a List (or use Collectors.joining() to get a single string)
            .collect(Collectors.toList());
            
        System.out.println(result); // Output: [A, B, C]
    }
}

Q23: To find the middle of a linked list in a single iteration, you can use the Tortoise and Hare Algorithm (also known as the Fast and Slow Pointer technique)

The core idea is to use two pointers starting at the head of the list:

Slow Pointer (Tortoise): Moves one step at a time.
Fast Pointer (Hare): Moves two steps at a time.

Because the fast pointer moves exactly twice as fast as the slow pointer, by the time the fast pointer reaches the end of the list, the slow pointer will be positioned exactly at the middle node

public class LinkedList {
    Node head;

    static class Node {
        int data;
        Node next;
        Node(int d) { data = d; next = null; }
    }

    public Node findMiddle() {
        if (head == null) return null;

        Node slow = head;
        Node fast = head;

        // Traverse in a single pass
        while (fast != null && fast.next != null) {
            slow = slow.next;       // Move 1 step
            fast = fast.next.next;  // Move 2 steps
        }

        // When fast reaches the end, slow is at the middle
        return slow;
    }
}

Q24 :Given a nxn matrix where n is odd, sum up elements in both diagonals

To sum both diagonals of an \(n \times n\) matrix (where \(n\) is odd) in \(O(n)\) time: iterate through rows \(i\) from \(0\) to \(n-1\), adding the primary (matrix[i][i]) and secondary (matrix[i][n - 1 - i]) elements. Since \(n\) is odd, subtract the center element at [n/2][n/2] once to prevent double-counting

public class DiagonalSum {
    public static int getDiagonalSum(int[][] matrix) {
        int n = matrix.length;
        int totalSum = 0;

        for (int i = 0; i < n; i++) {
            // Add primary diagonal element
            totalSum += matrix[i][i];
            
            // Add secondary diagonal element
            totalSum += matrix[i][n - 1 - i];
        }

        // Since n is odd, the center element overlaps and is counted twice.
        // Subtract it once to get the exact sum of unique diagonal items.
        int centerIndex = n / 2;
        totalSum -= matrix[centerIndex][centerIndex];

        return totalSum;
    }

    public static void main(String[] args) {
        // Example 3x3 matrix where n is odd
        int[][] matrix = {
            {1, 2, 3},
            {4, 5, 6},
            {7, 8, 9}
        };

        System.out.println("Total Diagonal Sum: " + getDiagonalSum(matrix)); 
        // Output: 1 + 5 + 9 + 3 + 5 + 7 - 5 = 25
    }
}

ComplexityTime Complexity: \(\mathcal{O}(n)\), as it executes a single loop running \(n\) times.Space Complexity: \(\mathcal{O}(1)\) auxiliary space.

Q25: Using Java 8 streams api find Given a nxn matrix where n is odd, sum up elements in both diagonals

import java.util.List;
import java.util.stream.IntStream;

public class DiagonalSum {
    public static int sumOddDiagonals(List<List<Integer>> matrix) {
        int n = matrix.size();
        
        // Summing both diagonals without excluding the overlap yet
        int totalSum = IntStream.range(0, n)
            .map(i -> matrix.get(i).get(i) + matrix.get(i).get(n - 1 - i))
            .sum();
            
        // Subtract center element once since diagonals intersect at the middle for odd n
        int centerVal = matrix.get(n / 2).get(n / 2);
        
        return totalSum - centerVal;
    }
}

Q28: BlockingQueue


A BlockingQueue is a thread-safe queue from java.util.concurrent that is ideal for producer-consumer problems in Java and Spring Boot services. Producers put work into the queue, and consumers take work from the queue. The queue handles waiting automatically when it is full or empty.

What is a BlockingQueue?

A BlockingQueue supports blocking operations:

Producer waits when the queue is full and uses put().

Consumer waits when the queue is empty and uses take().

Thread-safe operations without manual synchronization for most use cases.

Useful for asynchronous processing such as background jobs, event processing, logging, notifications, and buffering requests.

Common BlockingQueue implementations

Implementation

Use case

ArrayBlockingQueue

Fixed-size queue with bounded capacity.

LinkedBlockingQueue

Optionally bounded queue; commonly used in producer-consumer systems.

PriorityBlockingQueue

Processes elements according to priority.

DelayQueue

Processes elements only after a delay has expired.

SynchronousQueue

Direct handoff between producer and consumer.

Important methods

Method

Behavior

put(E e)

Inserts an element, waiting if the queue is full.

take()

Retrieves and removes an element, waiting if the queue is empty.

offer(E e)

Inserts if space is available; returns false if full.

offer(E e, timeout, unit)

Waits for a limited time to insert an element.

poll()

Retrieves and removes an element, or returns null if empty.

poll(timeout, unit)

Waits for a limited time to retrieve an element.

peek()

Returns the head element without removing it.

remainingCapacity()

Returns available capacity in a bounded queue.

Producer-consumer flow

Flow

Producer → put(task) → BlockingQueue → take() → Consumer

The producer creates tasks or events and adds them to the queue.

The consumer continuously takes tasks from the queue and processes them.

If the queue is full, the producer waits when using put().

If the queue is empty, the consumer waits when using take().

Plain Java example:

import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class ProducerConsumerDemo {

    private static final BlockingQueue<String> queue =
            new ArrayBlockingQueue<>(5);

    public static void main(String[] args) {

        // Producer
        new Thread(() -> {
            try {
                for (int i = 1; i <= 10; i++) {
                    String item = "Task-" + i;
                    queue.put(item); // waits if queue is full
                    System.out.println("Produced: " + item);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }).start();

        // Consumer
        new Thread(() -> {
            try {
                while (true) {
                    String item = queue.take(); // waits if queue is empty
                    System.out.println("Consumed: " + item);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }).start();
    }
}

Better Spring Boot approach with ExecutorService

Instead of manually creating threads, use a managed executor. This gives better control over thread pool size, shutdown, and monitoring.

import jakarta.annotation.PostConstruct;
import org.springframework.stereotype.Service;

import java.util.concurrent.BlockingQueue;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

@Service
public class ConsumerService {

    private final BlockingQueue<String> taskQueue;
    private final ExecutorService executor = Executors.newFixedThreadPool(2);

    public ConsumerService(BlockingQueue<String> taskQueue) {
        this.taskQueue = taskQueue;
    }

    @PostConstruct
    public void startConsumers() {
        for (int i = 0; i < 2; i++) {
            executor.submit(() -> {
                try {
                    while (true) {
                        String task = taskQueue.take();
                        processTask(task);
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            });
        }
    }

    private void processTask(String task) {
        System.out.println(Thread.currentThread().getName()
                + " processed: " + task);
    }
}
When to use BlockingQueue

Asynchronous background processing inside a single Spring Boot application.

Rate limiting or buffering incoming requests before processing.

Producer-consumer workloads such as email sending, file processing, report generation, or event handling.

Situations where in-memory communication between threads is sufficient.

Limitations in microservices

Important: BlockingQueue is an in-memory queue. It works only within a single JVM instance. For communication between distributed Spring Boot microservices, use a durable messaging system such as
Apache Kafka
,
RabbitMQ
, or
Google Cloud Pub/Sub
.

Best practices

Use a bounded queue such as ArrayBlockingQueue to avoid memory issues.

Prefer offer(timeout) when you do not want producers to block indefinitely.

Handle InterruptedException by restoring the interrupted status with Thread.currentThread().interrupt().

Use ExecutorService or Spring’s TaskExecutor instead of creating raw threads manually.

Monitor queue size and processing rate in production systems.

Interview answer summary

A BlockingQueue is a thread-safe queue that supports blocking operations for producers and consumers. In a producer-consumer pattern, producers add items using put() or offer(), and consumers retrieve items using take() or poll(). In Spring Boot, a shared BlockingQueue bean can be injected into producer and consumer services, while consumers run in background threads or an ExecutorService. For distributed microservices, message brokers such as Kafka or RabbitMQ are preferred over an in-memory BlockingQueue

Q29: Internal working of Synchronized method and Block

What is synchronized?

synchronized is a Java keyword that provides mutual exclusion (mutex) and memory visibility.

It ensures:

Only one thread executes a critical section at a time.
Changes made by one thread are visible to other threads after the lock is released.
How JVM implements synchronized

Every Java object has an associated monitor (lock) managed by the JVM.

When a thread enters a synchronized region:

JVM checks the object's monitor.
If the monitor is free:
The thread acquires the monitor.
Enters the synchronized code.
If another thread already owns the monitor:
The current thread becomes BLOCKED.
When the owning thread exits the synchronized region:
The monitor is released.
One blocked thread acquires it.
          Object
      +---------------+
      |     Data      |
      |---------------|
      | Monitor Lock  |
      +---------------+
             ▲
             │
        Thread acquires
Internal Working of a Synchronized Method

Example:

    public synchronized void increment() {
        count++;
    }
}
JVM Bytecode

The JVM marks the method with the ACC_SYNCHRONIZED flag.

Conceptually, it behaves like:

Acquire object's monitor

try {
    increment()
}
finally {
    Release object's monitor
}

The JVM automatically:

acquires the monitor before entering the method,
releases it when exiting normally or due to an exception.

Java monitors are reentrant, meaning a thread that already owns a lock can acquire it again.

The JVM maintains a hold count for the monitor. Each acquisition increments the count; each exit decrements it. The monitor is released only when the count reaches zero.

Lock States (Modern JVM)

The JVM may optimize monitor acquisition using different lock states:

Unlocked
     |
     ↓
Biased Locking (older JDKs; disabled by default in later JDKs and removed in recent JDKs)
     ↓
Lightweight Lock
     ↓
Heavyweight Monitor Lock

Modern JDKs (such as Java 17 and later) no longer use biased locking, but lightweight and heavyweight monitor optimizations are still part of JVM synchronization.

Main Memory
     ↑
Flush local changes

When another thread enters:

Read latest values

Interview Answer (2-minute version)

Every Java object has an associated monitor (intrinsic lock). A synchronized method acquires the object's monitor before execution and releases it automatically when the method exits; the JVM represents this with the ACC_SYNCHRONIZED method flag. A synchronized block uses explicit monitorenter and monitorexit bytecode instructions. If another thread already owns the monitor, the requesting thread enters the BLOCKED state until the monitor becomes available. Java monitors are reentrant, so the same thread can acquire the same lock multiple times. Synchronization provides both mutual exclusion and memory visibility through the Java Memory Model's happens-before guarantees.

Q33:LRU Cache implementation using java 8 and how to make thread safe

Solution:

What is an LRU Cache?

An LRU cache has a fixed capacity.

When it becomes full:

Adding a new entry evicts the least recently used entry.
Every get() or put() operation marks the accessed entry as most recently used.

Example (capacity = 3):

put(1,A)
Cache: [1]

put(2,B)
Cache: [1,2]

put(3,C)
Cache: [1,2,3]

get(1)
Cache: [2,3,1]   // 1 becomes most recently used

put(4,D)
Evict 2
Cache: [3,1,4]

------------

Approach 1: Java 8 using LinkedHashMap (Recommended)

LinkedHashMap already maintains insertion or access order.

By enabling accessOrder=true, it automatically moves accessed entries to the end.

import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCache<K, V> extends LinkedHashMap<K, V> {

    private final int capacity;

    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // true = access order
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }

    public static void main(String[] args) {

        LRUCache<Integer, String> cache = new LRUCache<>(3);

        cache.put(1, "A");
        cache.put(2, "B");
        cache.put(3, "C");

        System.out.println(cache);

        cache.get(1);

        System.out.println(cache);

        cache.put(4, "D");

        System.out.println(cache);
    }
}

Output:

{1=A, 2=B, 3=C}

{2=B, 3=C, 1=A}

{3=C, 1=A, 4=D}

How to Make It Thread-Safe

LinkedHashMap is not thread-safe.

If multiple threads call get() and put() concurrently:

Data races can occur.
The linked list order may become inconsistent.
Entries can be lost or the map can become corrupted

Option 1: Synchronize All Access (Simple)
public synchronized V getValue(K key) {
    return super.get(key);
}

public synchronized V putValue(K key, V value) {
    return super.put(key, value);
}

Or synchronize externally:

synchronized (cache) {
    cache.put(1, "A");
}

Pros

Easy to implement.

Cons

Only one thread can access the cache at a time.
Option 2: ReentrantLock (Better Control)
private final ReentrantLock lock = new ReentrantLock();

public V get(K key) {
    lock.lock();
    try {
        return super.get(key);
    } finally {
        lock.unlock();
    }
}

public V put(K key, V value) {
    lock.lock();
    try {
        return super.put(key, value);
    } finally {
        lock.unlock();
    }
}

Pros

Explicit locking.
Supports tryLock(), fairness, and interruptible locks.
Option 3: ReadWriteLock

Normally, a ReadWriteLock allows multiple readers and one writer.

However, for an LRU cache, get() is effectively a write operation because it changes the access order.

get()

↓

Move node to tail

↓

Modify linked list

Therefore, both get() and put() require the write lock.

Not sufficient.

Why?

ConcurrentHashMap

↓

Thread-safe map

↓

NO access order

↓

Cannot evict LRU automatically

An LRU cache needs:

Fast lookup.
Ordered access tracking.
Safe eviction.

ConcurrentHashMap only solves the first part.

Option 5: ConcurrentHashMap + Doubly Linked List

This is how many high-performance caches are designed.

ConcurrentHashMap

↓

Key → Node

↓

Node

↓

Prev

↓

Next

↓

Value

Each access:

Finds the node in O(1).
Moves it to the tail of the doubly linked list.
Evicts the head when capacity is exceeded.

This design requires careful synchronization around list updates.

Summarised: Interview Answer (2 minutes)

An LRU cache keeps the most recently used entries and evicts the least recently used entry when the cache reaches its capacity. In Java, the simplest implementation is to extend LinkedHashMap with accessOrder=true and override removeEldestEntry(). Internally, LinkedHashMap combines a hash table for O(1) lookups with a doubly linked list for maintaining access order. Since get() changes the access order, both get() and put() modify the internal state. LinkedHashMap is not thread-safe, so I would protect access with synchronization or a ReentrantLock for a simple implementation. For highly concurrent production systems, I would use a library such as Caffeine, which provides efficient, thread-safe caching with advanced eviction policies and significantly better scalability than a custom implementation.

        int[] groupIds = new int[input.length];

            groupIds[i] = groupIds[i - 1] + (input[i].equals(input[i - 1]) ? 0 : 1);
        }

        // Step 2: group indices by groupId (LinkedHashMap preserves order), then map to "value-count"
        List<String> result = IntStream.range(0, input.length)
                .boxed()
                .collect(Collectors.groupingBy(
                        i -> groupIds[i],
                        LinkedHashMap::new,
                        Collectors.toList()))
                .values()
                .stream()
                .map(indices -> input[indices.get(0)] + "-" + indices.size())
                .collect(Collectors.toList());

        System.out.println(result);
    }
}

Q40:Scenario:order system -> my UI is calling order module , shipping module ,payment reporting module ,  identify issues and resolve failures ,fix my architecture using spring boot , java, microservices, kafka, postgresql,

Solution:

What's wrong with the current setup
Cascading failures — if Payment or Shipping is slow/down, the UI call chain blocks or fails entirely, even though Order creation itself may have succeeded.

No transactional consistency — an order can get created but shipping/payment can silently fail with nothing to reconcile it (no compensation logic).

Reporting coupled to the critical path — reporting/analytics should never be able to slow down or fail a live order request; it's read-only, non-critical, and usually async by nature.

No retry/backoff or circuit breaking — a transient blip in one module takes down the whole flow instead of degrading gracefully.

Tight coupling / shared responsibility — the UI (or a thin gateway) is doing orchestration work that belongs in a backend service.

No idempotency — retries without idempotency keys risk duplicate orders/charges/shipments.

Key architectural changes

1. UI never talks to backend services directly. It only calls the API Gateway (Spring Cloud Gateway), which forwards to the Order Service. The Order Service is the only orchestrator.

2. Order creation is synchronous, everything downstream is asynchronous via Kafka. The Order Service saves the order (status PENDING) to its own Postgres schema, publishes an order-created event, and returns immediately to the UI. Payment, Shipping, and Reporting each consume independently — a slow or down Payment service no longer blocks order creation.

3. Database-per-service. Each service owns its own Postgres schema/instance — no shared tables. Reporting builds a read-model by consuming events, not by querying other services' databases.

4. Saga pattern for consistency, since there's no distributed transaction across services:

Order Service publishes order-created
Payment Service consumes it, charges the card, publishes payment-succeeded or payment-failed
Order Service consumes that and updates order status; on failure, publishes a order-cancelled compensating event that Shipping/Reporting also consume

5. Resilience patterns (via Resilience4j on any place still synchronous, e.g. gateway → order service):

@CircuitBreaker(name = "orderService", fallbackMethod = "fallback")
@Retry(name = "orderService")
@TimeLimiter(name = "orderService")
public CompletableFuture<OrderResponse> createOrder(OrderRequest req) {
    return CompletableFuture.supplyAsync(() -> orderClient.create(req));
}

6. Idempotency on every consumer — use an idempotency key (e.g. order ID + event type) stored per-service so retried Kafka messages don't double-charge or double-ship:

@KafkaListener(topics = "order-events", groupId = "payment-service")
public void handle(OrderEvent event) {
    if (processedEventRepo.existsById(event.getEventId())) return; // idempotent skip
    // process payment...
    processedEventRepo.save(new ProcessedEvent(event.getEventId()));
}

7. Dead-letter topics + retry for genuine failures (e.g. order-events.DLT), so a bad message doesn't block the partition, and you get a queue to inspect/replay instead of silent data loss.

public class SecondNonRepeated {

    public static void main(String[] args) {

        String str = "javaarticles";

        Character ch =
                str.chars()

                   // Step 1: Convert int → char
                   .mapToObj(c -> (char) c)

                   // Step 2: Count frequency with order preserved
                   .collect(Collectors.groupingBy(

                           // Key = character itself
                           Function.identity(),

                           // VERY IMPORTANT: preserve insertion order
                           LinkedHashMap::new,

                           // Count occurrences
                           Collectors.counting()
                   ))

                   // Step 3: Convert Map → Stream
                   .entrySet()
                   .stream()

                   // Step 4: Filter non-repeated characters
                   .filter(e -> e.getValue() == 1)

                   // Step 5: Skip first non-repeated
                   .skip(1)

                   // Step 6: Extract character
                   .map(Map.Entry::getKey)

                   // Step 7: Get result
                   .findFirst()

                   // Step 8: Handle safely
                   .orElse(null);

        System.out.println(ch);
    }
}

Pass 1: Iterate through the string to count the frequency of each character. This also takes (O(n)) time.Combining these operations results in (O(n) + O(n) = O(2n)), which simplifies to (O(n)).

Q51:LRU Cache in JAVA

import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCacheLinkedHashMap<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCacheLinkedHashMap(int capacity) {
        // initialCapacity, loadFactor, accessOrder (true sets it to LRU tracking)
        super(capacity, 0.75f, true);
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        // Automatically evicts the least recently used item when capacity is exceeded
        return size() > capacity;
    }

    public static void main(String[] args) {
        LRUCacheLinkedHashMap<Integer, String> cache = new LRUCacheLinkedHashMap<>(2);
        cache.put(1, "A");
        cache.put(2, "B");
        cache.get(1);       // Accessing 1 makes it Most Recently Used
        cache.put(3, "C");  // Exceeds capacity. Evicts 2 (LRU)
        
        System.out.println(cache); // Output: {1=A, 3=C}
    }
}

Q52:LFU Cache in JAVA

import java.util.HashMap;
import java.util.LinkedHashSet;
import java.util.Map;

public class LFUCache<K, V> {
    private final int capacity;
    private int minFrequency;
    private final Map<K, V> cache;
    private final Map<K, Integer> keyFrequency;
    private final Map<Integer, LinkedHashSet<K>> frequencyList;

    public LFUCache(int capacity) {
        this.capacity = capacity;
        this.minFrequency = 0;
        this.cache = new HashMap<>();
        this.keyFrequency = new HashMap<>();
        this.frequencyList = new HashMap<>();
    }

    public V get(K key) {
        if (!cache.containsKey(key)) {
            return null;
        }
        int frequency = keyFrequency.get(key);
        keyFrequency.put(key, frequency + 1);
        frequencyList.get(frequency).remove(key);

        if (frequencyList.get(frequency).isEmpty()) {
            frequencyList.remove(frequency);
            if (minFrequency == frequency) {
                minFrequency++;
            }
        }

        frequencyList.computeIfAbsent(frequency + 1, k -> new LinkedHashSet<>()).add(key);
        return cache.get(key);
    }

    public void put(K key, V value) {
        if (capacity <= 0) {
            return;
        }

        if (cache.containsKey(key)) {
            cache.put(key, value);
            get(key);  // Update the frequency of the key
            return;
        }

        if (cache.size() >= capacity) {
            K evict = frequencyList.get(minFrequency).iterator().next();
            frequencyList.get(minFrequency).remove(evict);
            if (frequencyList.get(minFrequency).isEmpty()) {
                frequencyList.remove(minFrequency);
            }
            cache.remove(evict);
            keyFrequency.remove(evict);
        }

        cache.put(key, value);
        keyFrequency.put(key, 1);
        minFrequency = 1;
        frequencyList.computeIfAbsent(1, k -> new LinkedHashSet<>()).add(key);
    }

    public static void main(String[] args) {
        LFUCache<Integer, String> lfuCache = new LFUCache<>(3);

        lfuCache.put(1, "one");
        lfuCache.put(2, "two");
        lfuCache.put(3, "three");
        System.out.println("Cache after adding 1, 2, 3: " + lfuCache.cache);

        lfuCache.get(1);
        lfuCache.get(1);

public class Geeks {

    // Linear-search function to find the index of an element
    public static int findIndex(int a[], int t)
    {
        if (a == null)
            return -1;

        int len = a.length;
        int i = 0;

        // traverse in the array
        while (i < len) {

            // if the i-th element is t
            // then return the index
            if (a[i] == t) {
                return i;
            }
            else {
                i = i + 1;
            }
        }
      
        return -1;
    }

  
    public static void main(String[] args)
    {
        int[] a = { 5, 4, 6, 1, 3, 2, 7, 8, 9 };
		int t = 7;
      
        // find the index of 7
        System.out.println(findIndex(a, t));
    }
}

import java.util.*;
import java.util.stream.Collectors;

public class SortHashMapByValue {
    public static void main(String[] args) {
        Map<Integer, String> map = new HashMap<>();
        map.put(1, "x");
        map.put(2, "s");
        map.put(3, "z");

        // Sort by value (ascending)
        Map<Integer, String> sortedMap = map.entrySet().stream()
                .sorted(Map.Entry.comparingByValue())
                .collect(Collectors.toMap(
                        Map.Entry::getKey,
                        Map.Entry::getValue,
                        (v1, v2) -> v1,
                        LinkedHashMap::new
                ));

        System.out.println("Sorted Map: " + sortedMap);
    }
}

Key Steps:
.stream() & .sorted(): Converts the map to a stream and uses Map.Entry.comparingByValue() to sort by values.
.collect(): Uses Collectors.toMap to collect results, specifically using LinkedHashMap::new to maintain the sorted order.

public class SimpleBinarySearch {

    // Returns the index of the target if found, otherwise returns -1
    public static int binarySearch(int[] arr, int target) {
        int low = 0;
        int high = arr.length - 1;

        while (low <= high) {
            // Calculates the middle index safely to prevent integer overflow
            int mid = low + (high - low) / 2; 

            // Check if the target is at the middle index
            if (arr[mid] == target) {
                return mid; 
            }
            // If target is larger, ignore the left half
            if (arr[mid] < target) {
                low = mid + 1;
            } 
            // If target is smaller, ignore the right half
            else {
                high = mid - 1;
            }
        }

        // Return -1 if the element is not present in the array
        return -1; 
    }

    public static void main(String[] args) {
        // The input array MUST be sorted for binary search to work
        int[] sortedArray = {2, 5, 8, 12, 16, 23, 38, 56, 72};
        int targetValue = 23;

        int resultIndex = binarySearch(sortedArray, targetValue);

        if (resultIndex != -1) {
            System.out.println("Element found at index: " + resultIndex);
        } else {
            System.out.println("Element not found in the array.");
        }
    }
}

Q94:Selection Sort algorithm

import java.util.Arrays;

public class SequentialSort {
    public static void main(String[] args) {
        int[] numbers = {64, 25, 12, 22, 11};
        
        System.out.println("Original array: " + Arrays.toString(numbers));
        
        // Sequential / Selection Sort Logic
        for (int i = 0; i < numbers.length - 1; i++) {
            int minIndex = i; // Assume the current position holds the minimum
            
            // Scan the remaining unsorted part sequentially
            for (int j = i + 1; j < numbers.length; j++) {
                if (numbers[j] < numbers[minIndex]) {
                    minIndex = j; // Update index if a smaller element is found
                }
            }
            
            // Swap the found minimum element with the current element
            int temp = numbers[minIndex];
            numbers[minIndex] = numbers[i];
            numbers[i] = temp;
        }
        
        System.out.println("Sorted array:   " + Arrays.toString(numbers));
    }
}

Q96:Quick Sort algorithm

import java.util.Arrays;

public class QuickSortExample {
    public static void main(String[] args) {
        int[] data = {9, 7, 5, 11, 12, 2, 14, 3, 10, 6};
        quickSort(data, 0, data.length - 1);
        System.out.println("Sorted: " + Arrays.toString(data));
    }

    public static void quickSort(int[] arr, int low, int high) {
        if (low < high) {
            int pi = partition(arr, low, high);
            quickSort(arr, low, pi - 1);
            quickSort(arr, pi + 1, high);
        }
    }

    private static int partition(int[] arr, int low, int high) {
        int pivot = arr[high], i = (low - 1);
        for (int j = low; j < high; j++) {
            if (arr[j] <= pivot) swap(arr, ++i, j);
        }
        swap(arr, i + 1, high);
        return i + 1;
    }

    private static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

Q98 :mergeSort

public static void mergeSort(int[] a, int n) {
    if (n < 2) {
        return;
    }
    int mid = n / 2;
    int[] l = new int[mid];
    int[] r = new int[n - mid];

    for (int i = 0; i < mid; i++) {
        l[i] = a[i];
    }
    for (int i = mid; i < n; i++) {
        r[i - mid] = a[i];
    }
    mergeSort(l, mid);
    mergeSort(r, n - mid);

    merge(a, l, r, mid, n - mid);
}

public static void merge(
  int[] a, int[] l, int[] r, int left, int right) {
 
    int i = 0, j = 0, k = 0;
    while (i < left && j < right) {
        if (l[i] <= r[j]) {
            a[k++] = l[i++];
        }
        else {
            a[k++] = r[j++];
        }
    }
    while (i < left) {
        a[k++] = l[i++];
    }
    while (j < right) {
        a[k++] = r[j++];
    }
}

Q99 : SimpleMergeSort

import java.util.Arrays;
import java.util.stream.IntStream;
import java.util.stream.Stream;

public class SimpleMergeSort {

    public static void main(String[] args) {
        int[] actual = {5, 1, 6, 2, 3, 4};
        
        System.out.println("Original: " + Arrays.toString(actual));
        
        int[] sorted = mergeSort(actual);
        
        System.out.println("Sorted:   " + Arrays.toString(sorted));
    }

    public static int[] mergeSort(int[] arr) {
        if (arr.length <= 1) {
            return arr;
        }
        
        int mid = arr.length / 2;
        
        return merge(
            mergeSort(Arrays.copyOfRange(arr, 0, mid)),
            mergeSort(Arrays.copyOfRange(arr, mid, arr.length))
        );
    }

    // Pure merge using streams (functional style)
    private static int[] merge(int[] left, int[] right) {
        // If one array is empty, return the other
        if (left.length == 0) return right;
        if (right.length == 0) return left;
        
        // Recursive merge using streams
        if (left[0] <= right[0]) {
            return IntStream.concat(
                IntStream.of(left[0]),
                Arrays.stream(merge(
                    Arrays.copyOfRange(left, 1, left.length),
                    right
                ))
            ).toArray();
        } else {
            return IntStream.concat(
                IntStream.of(right[0]),
                Arrays.stream(merge(
                    left,
                    Arrays.copyOfRange(right, 1, right.length)
                ))
            ).toArray();
        }
    }
}

Q109 : print even and odd numbers using multithreading in jadva one even and next odd

To print alternating even and odd numbers sequentially using multithreading in Java, you must coordinate two separate threads using inter-thread communication mechanisms like wait() and notify(). 

This technique avoids race conditions and forces one thread to print an even number followed immediately by the other thread printing an odd number


public class EvenOddSequencer {
    private int counter = 2; // Starting with the first even number
    private final int limit;

    public EvenOddSequencer(int limit) {
        this.limit = limit;
    }

    // Method executed by the Even thread
    public void printEven() {
        synchronized (this) {
            while (counter <= limit) {
                // If it's an odd number's turn, wait
                while (counter % 2 != 0) {
                    try {
                        wait();
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                }

                // Double check condition before printing after waking up
                if (counter <= limit) {
                    System.out.println(Thread.currentThread().getName() + ": " + counter);
                    counter++;
                    notify(); // Wake up the Odd thread
                }
            }
        }
    }

    // Method executed by the Odd thread
    public void printOdd() {
        synchronized (this) {
            while (counter <= limit) {
                // If it's an even number's turn, wait
                while (counter % 2 == 0) {
                    try {
                        wait();
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                }

                // Double check condition before printing after waking up
                if (counter <= limit) {
                    System.out.println(Thread.currentThread().getName() + ": " + counter);
                    counter++;
                    notify(); // Wake up the Even thread
                }
            }
        }
    }

    public static void main(String[] args) {
        int maxLimit = 10;
        EvenOddSequencer sequencer = new EvenOddSequencer(maxLimit);

        // Create the even thread
        Thread evenThread = new Thread(sequencer::printEven, "Even-Thread");
        
        // Create the odd thread
        Thread oddThread = new Thread(sequencer::printOdd, "Odd-Thread");

        // Start both threads
        evenThread.start();
        oddThread.start();
    }
}

Q111: Here is the complete, self-contained implementation using IntStream, CompletableFuture, and synchronized blocks to guarantee that one even number prints first, followed by the next odd number


import java.util.concurrent.CompletableFuture;
import java.util.stream.IntStream;

public class AlternatingEvenOdd {
    private static final int LIMIT = 10;
    private static final Object lock = new Object();
    // Since requirement specifies "one even and next odd", we track the turn.
    // true = Even thread turn, false = Odd thread turn.
    private static boolean isEvenTurn = true; 

    public static void main(String[] args) {
        // 1. Stream generating even numbers processed by the Even Thread
        CompletableFuture<Void> evenTask = CompletableFuture.runAsync(() -> {
            IntStream.rangeClosed(1, LIMIT)
                     .filter(n -> n % 2 == 0)
                     .forEach(AlternatingEvenOdd::printEven);
        });

        // 2. Stream generating odd numbers processed by the Odd Thread
        CompletableFuture<Void> oddTask = CompletableFuture.runAsync(() -> {
            IntStream.rangeClosed(1, LIMIT)
                     .filter(n -> n % 2 != 0)
                     .forEach(AlternatingEvenOdd::printOdd);
        });

        // 3. Keep main thread alive until both streams finish executing
        CompletableFuture.allOf(evenTask, oddTask).join();
    }

    private static void printEven(int number) {
        synchronized (lock) {
            // Wait while it is the Odd thread's turn
            while (!isEvenTurn) {
                try {
                    lock.wait();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
            // Print the even number
            System.out.println(Thread.currentThread().getName() + " (Even) -> " + number);
            // Flip the flag to pass control to the Odd thread
            isEvenTurn = false;
            lock.notifyAll();
        }
    }

    private static void printOdd(int number) {
        synchronized (lock) {
            // Wait while it is the Even thread's turn
            while (isEvenTurn) {
                try {
                    lock.wait();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
            // Print the odd number
            System.out.println(Thread.currentThread().getName() + " (Odd)  -> " + number);
            // Flip the flag to pass control back to the Even thread
            isEvenTurn = true;
            lock.notifyAll();
        }
    }
}

Q117: Scenario Question Race condition bug

public class RequestTracker {

    // Tracks the current number of active concurrent requests

    private Integer activeRequests = 0;
 
   
    public void logRequestStart() {

        synchronized (activeRequests) {

            activeRequests++;

        }

    }
 
    
public void logRequestEnd() {

        synchronized (activeRequests) {

            activeRequests--;

        }

    }
 
    
public int getActiveRequests() {

        return activeRequests;

    }

}


Solution:

You are synchronizing on activeRequests, which is an Integer object

1.Object Mutation: The expressions activeRequests++ and activeRequests-- do not modify the existing Integer object. They create a brand new Integer object (due to autoboxing) and reassign the activeRequests reference to it
2. Broken Locks: Because the reference changes every time a thread enters the block, subsequent threads will synchronize on a different object instance. This completely breaks the mutual exclusion lock, allowing multiple threads to enter the critical section simultaneously.

3. NullPointerException: activeRequests could eventually point to an integer cached by the JVM or a new instance, but if multiple threads reassign it concurrently, it can also lead to unpredictable race conditions or NullPointerException.

Fix:

Option 1: Use AtomicInteger (Best Practice)

It eliminates the need for manual synchronized blocks by using non-blocking CPU instructions.

import java.util.concurrent.atomic.AtomicInteger;

public class RequestTracker {
    // Thread-safe without explicit locking
    private final AtomicInteger activeRequests = new AtomicInteger(0);
 
    public void logRequestStart() {
        activeRequests.incrementAndGet();
    }
 
    public void logRequestEnd() {
        activeRequests.decrementAndGet();
    }
 
    public int getActiveRequests() {
        return activeRequests.get();
    }
}


Option 2: Synchronize on a Final Lock Object

If you want to keep the primitive/wrapper logic, you must synchronize on a dedicated, unchanging lock object.

public class RequestTracker {
    // Dedicated lock object that never changes
    private final Object lock = new Object();
    private int activeRequests = 0; // Use primitive int
 
    public void logRequestStart() {
        synchronized (lock) {
            activeRequests++;
        }
    }
 
    public void logRequestEnd() {
        synchronized (lock) {
            activeRequests--;
        }
    }
 
    public int getActiveRequests() {
        synchronized (lock) {
            return activeRequests;
        }
    }
}

Option 3: Synchronize the Methods

we can synchronize the entire method signature. This locks the current instance (this) of the RequestTracker class.
public class RequestTracker {
    private int activeRequests = 0;
 
    public synchronized void logRequestStart() {
        activeRequests++;
    }
 
    public synchronized void logRequestEnd() {
        activeRequests--;
    }
 
    public synchronized int getActiveRequests() {
        return activeRequests;
    }
}

import java.util.List;
import java.util.Objects;

public class DuplicateDetector {

    /**
     * Returns true if the input list contains any duplicate vulnerability
     * (same title AND same severityScore), otherwise false.
     */
    public static boolean hasDuplicates(List<Vulnerability> items) {
        if (items == null || items.size() <= 1) {
            return false;
        }

        // Compare total count to distinct count using equals/hashCode
        long distinctCount = items.stream()
                                  .distinct()
                                  .count();

        return distinctCount < items.size();
    }
}

class Vulnerability {
    private final String title;        // e.g., "SQL Injection"
    private final double severityScore; // e.g., 9.8

    public Vulnerability(String title, double severityScore) {
        this.title = title;
        this.severityScore = severityScore;
    }

    // Required for distinct() to work properly on title AND severityScore
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Vulnerability that = (Vulnerability) o;
        return Double.compare(that.severityScore, severityScore) == 0 &&
               Objects.equals(title, that.title);
    }

    @Override
    public int hashCode() {
        return Objects.hash(title, severityScore);
    }
}

Input - "abc cab bac abcd def cdba"
output - abc- 3 , abcd - 2 , def - 1

Solution:

import java.util.*;
import java.util.stream.*;
import java.util.function.Function;

public class AnagramCounter {
    public static void main(String[] args) {
        String input = "abc cab bac abcd def cdba";

        Map<String, Long> result = Arrays.stream(input.split(" "))
            .collect(Collectors.groupingBy(word -> {
                // Sort characters of the word to create a unique key for anagrams
                char[] chars = word.toCharArray();
                Arrays.sort(chars);
                return new String(chars);
            }, Collectors.counting()));

        // Display results in the required format
        String output = result.entrySet().stream()
            .map(e -> e.getKey() + " - " + e.getValue())
            .collect(Collectors.joining(" , "));

        System.out.println(output);
    }
}

Explanation of Steps:

Splitting the Input: The String.split(" ") method converts the space-separated string into an array of individual words.

Generating Anagram Keys: For each word, the characters are converted to a char[] and sorted using Arrays.sort(). Words like "abc", "cab", and "bac" all result in the same key: "abc".

Grouping and Counting: The Collectors.groupingBy method organizes the words by these sorted keys, while Collectors.counting() calculates the frequency of each group.

Formatting Output: The final map is streamed to join the keys and values into the desired string format

Q132: SequentialPrinting

public class SequentialPrinting {
    private static int counter = 1;
    private static final int MAX = 6; // Max number to print
    private static final int THREADS_COUNT = 3;
    private static final Object lock = new Object();

    public static void main(String[] args) {
        // Create 3 threads with specific remainders: 1, 2, and 0 (for Thread 3)
        Thread t1 = new Thread(new PrinterTask(1), "Thread 1");
        Thread t2 = new Thread(new PrinterTask(2), "Thread 2");
        Thread t3 = new Thread(new PrinterTask(0), "Thread 3");

        t1.start();
        t2.start();
        t3.start();
    }

    static class PrinterTask implements Runnable {
        private final int remainder;

        PrinterTask(int remainder) {
            this.remainder = remainder;
        }

        @Override
        public void run() {
            while (counter <= MAX) {
                synchronized (lock) {
                    // Check if it is this thread's turn
                    while (counter <= MAX && counter % THREADS_COUNT != remainder) {
                        try {
                            lock.wait();
                        } catch (InterruptedException e) {
                            Thread.currentThread().interrupt();
                        }
                    }

                    // Print and increment if it's within the limit
                    if (counter <= MAX) {
                        System.out.println(Thread.currentThread().getName() + ": " + counter);
                        counter++;
                    }
                    
                    // Signal other threads to check the updated counter
                    lock.notifyAll();
                }
            }
        }
    }
}

import org.springframework.context.annotation.Configuration;

// Java classes
import java.time.Duration;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Configuration
public class RateLimiterConfig {

    @Bean
    public Map<String, Bucket> rateLimiterBuckets() {

        // Thread-safe Map
        // Stores buckets for different users/IPs/API Keys
        Map<String, Bucket> buckets = new ConcurrentHashMap<>();


        /*
         * Create Rate Limit Rule
         *
         * Maximum Capacity = 100 Tokens
         * Refill = 100 Tokens every 1 minute
         *
         * Meaning:
         *
         * User can make 100 requests immediately
         *
         * After consuming all tokens,
         * bucket gets refilled after 1 minute
         */
        Bandwidth limit =
                Bandwidth.classic(
                        100,
                        Refill.greedy(
                                100,
                                Duration.ofMinutes(1)
                        )
                );


        /*
         * Create Actual Bucket
         *
         * Bucket = Container holding tokens
         */
        Bucket defaultBucket =
                Bucket.builder()
                        .addLimit(limit)
                        .build();


        /*
         * Store bucket in map
         *
         * Key = default
         * Value = bucket object
         */
        buckets.put("default", defaultBucket);

        return buckets;
    }
}

Q141: LRU Cache (Least Recently Used)

Idea: Remove the item that was not used for the longest time.

LinkedHashMap with accessOrder=true automatically moves accessed entries to the end

import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCache<K, V> extends LinkedHashMap<K, V> {

    private final int capacity;

    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder=true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }

    public static void main(String[] args) {

        LRUCache<Integer, String> cache = new LRUCache<>(3);

        cache.put(1, "A");
        cache.put(2, "B");
        cache.put(3, "C");

        System.out.println(cache);

        cache.get(1); // Access key 1

        cache.put(4, "D"); // Evicts key 2

        System.out.println(cache);
    }
}

Q142: LFU Cache (Least Frequently Used)

Idea: Remove the item that has been used the least number of times.

import java.util.HashMap;
import java.util.Map;

public class LFUCache<K, V> {

    private final int capacity;

    private final Map<K, V> values = new HashMap<>();
    private final Map<K, Integer> frequencies = new HashMap<>();

    public LFUCache(int capacity) {
        this.capacity = capacity;
    }

    public V get(K key) {

        if (!values.containsKey(key)) {
            return null;
        }

        frequencies.put(key, frequencies.get(key) + 1);

        return values.get(key);
    }

    public void put(K key, V value) {

        if (values.size() >= capacity && !values.containsKey(key)) {
            evictLFU();
        }

        values.put(key, value);
        frequencies.put(key, frequencies.getOrDefault(key, 0) + 1);
    }

    private void evictLFU() {

        K leastUsedKey = null;
        int minFrequency = Integer.MAX_VALUE;

        for (Map.Entry<K, Integer> entry : frequencies.entrySet()) {

            if (entry.getValue() < minFrequency) {
                minFrequency = entry.getValue();
                leastUsedKey = entry.getKey();
            }
        }

        values.remove(leastUsedKey);
        frequencies.remove(leastUsedKey);

        System.out.println("Evicted: " + leastUsedKey);
    }

    public static void main(String[] args) {

        LFUCache<Integer, String> cache = new LFUCache<>(3);

        cache.put(1, "A");
        cache.put(2, "B");
        cache.put(3, "C");

        cache.get(1);
        cache.get(1);
        cache.get(2);

        cache.put(4, "D"); // Key 3 removed

        System.out.println(cache.values);
    }
}

Q143: TTL Cache (Time To Live)

Idea: Entries expire automatically after a fixed time.

Use ConcurrentHashMap and store expiry timestamp.

import java.util.concurrent.ConcurrentHashMap;

public class TTLCache<K, V> {

    private static class CacheEntry<V> {

        V value;
        long expiryTime;

        CacheEntry(V value, long expiryTime) {
            this.value = value;
            this.expiryTime = expiryTime;
        }
    }

    private final ConcurrentHashMap<K, CacheEntry<V>> cache =
            new ConcurrentHashMap<>();

    public void put(K key, V value, long ttlMillis) {

        long expiryTime = System.currentTimeMillis() + ttlMillis;

        cache.put(key, new CacheEntry<>(value, expiryTime));
    }

    public V get(K key) {

        CacheEntry<V> entry = cache.get(key);

        if (entry == null) {
            return null;
        }

        if (System.currentTimeMillis() > entry.expiryTime) {
            cache.remove(key);
            return null;
        }

        return entry.value;
    }

    public static void main(String[] args) throws Exception {

        TTLCache<String, String> cache = new TTLCache<>();

        cache.put("user1", "Rakesh", 3000);

        System.out.println(cache.get("user1"));

        Thread.sleep(4000);

        System.out.println(cache.get("user1"));
    }
}

Solution:

It will roll back.

By default, Spring's @Transactional annotation automatically rolls back the transaction if a RuntimeException (or any other unchecked exception) is thrown.

Unchecked Exceptions: RuntimeException and Error trigger automatic rollback.

Q151:how to solve the Partition Equal Subset Sum problem in Java streams api
	
Input: nums = [1,5,11,5]
Output: true
Explanation: The array can be partitioned as [1, 5, 5] and [11].


import java.util.*;
import java.util.stream.*;

public class PartitionEqualSubsetSum {

    public static boolean canPartition(int[] nums) {
        int sum = Arrays.stream(nums).sum();
        if (sum % 2 != 0) {
            return false;
        }

        int target = sum / 2;

        Set<Integer> achievableSums = Arrays.stream(nums)
            .boxed()
            .reduce(
                Collections.singleton(0), // identity: sum 0 is always achievable
                (set, num) -> Stream.concat(
                        set.stream(), // sums without `num`
                       set.stream().map(s -> s + num).filter(s -> s <= target) //sums with `num`
                    )
                    .collect(Collectors.toSet()),
                (s1, s2) -> {
                    throw new UnsupportedOperationException("sequential only");
                }
            );

        return achievableSums.contains(target);
    }

    public static void main(String[] args) {
        int[] nums = {1, 5, 11, 5};
        System.out.println(canPartition(nums)); // true
    }
}

Q152:Frequency Balanacing Problem


you are giving a string, task allocation of length n made of lowercase English letters
.
1. the character at index i represents the server assign at the i-th task 
2. each distinct letter represents a different server and the number of times a letter appears is the number of task assigned to that server.
 
In one operation you may perform exactly one of the following
 
1. Add a new task by inserting any lowercase letter 

2. Remove an existing task by deleting any one character from the string
 
 
our objective is to make the workload balanced meaning every server that appears in the final string has the same number of assigned tasks (all remaining letters must have equal frequency). Determine the min number of operations needed to reach a balanced workload. 
 

Solution:

import java.util.*;
import java.util.stream.*;

public class TaskAllocationBalance {

    public static int minOperations(String s) {
        // Step 1: frequency count per letter
        Map<Character, Long> freqMap = s.chars()
            .mapToObj(c -> (char) c)
            .collect(Collectors.groupingBy(c -> c, Collectors.counting()));

        if (freqMap.isEmpty()) {
            return 0; // empty string is trivially balanced
        }

        List<Integer> freqs = freqMap.values().stream()
            .map(Long::intValue)
            .collect(Collectors.toList());

        int maxFreq = freqs.stream()
		              .mapToInt(Integer::intValue)
					  .max().getAsInt();

        // Step 2: try every candidate target T from 1..maxFreq
        int best = IntStream.rangeClosed(1, maxFreq)
            .map(T -> freqs.stream()
                .mapToInt(f -> f >= T ? f - T : Math.min(T - f, f))
                .sum())
                .min()
                .getAsInt();

        return best;
    }

    public static void main(String[] args) {
        System.out.println(minOperations("aabbc"));      // 1
        System.out.println(minOperations("abc"));         // 0
        System.out.println(minOperations("aaabbbbcc"));   // 2
        System.out.println(minOperations("a"));           // 0
    }
}

Q157: How are Java Objects Stored in Memory?

https://www.geeksforgeeks.org/java/how-are-java-objects-stored-in-memory/

In Java, memory management is handled by the Java Virtual Machine (JVM). The breakdown of how objects are stored in memory:

All Java objects are dynamically stored in the heap memory.
References to these objects are stored in the stack memory.
Objects are created using the "new" keyword and are allocated in the heap memory.
Declaring a variable of a class type does not create an object it only creates references.
To allocate memory for the object in heap, we need to use the "new" keyword.
The Java Virtual Machine is responsible for memory management in Java and divides memory into several areas:

Heap Memory: Stores actual objects.
Stack Memory: Stores method call data, local variables, and references.
Other Areas: Include method area, metaspace (from Java 8), etc.
Memory Areas in Java
Now, let us go through each of the memory areas in detail.

1. Heap Memory

Heap memory is a part of Java memory management. When an object is created using the new keyword, Java allocates space for that object in the heap. The amount of memory allocated depends on the fields defined in the object's class and their respective data types.

Scanner sc = new Scanner(System.in)

Here, the Scanner object is stored in the heap, and the reference sc is stored in the stack

Note: Garbage collection in the heap area is mandatory for automatic memory management.

Heap Memory is divided into several regions:

Young Generation: The area within the heap where new objects are generally allocated.
Old Generation: The area within the heap where long-livedmetadata Objects are stored after surviving multiple garbage collection cycles.
Permanent Generation: It stores metadata about classes and methods in Java 7 and earlier versions.

Starting with Java 8, the old permanent generation space was removed and replaced by metaspace. Metaspace uses native memory outside the main heap. This change helps Java to handle class metadata better and also reduces the chances of errors caused by permanent generation.

When the new keyword is called, the JVM allocates memory for that object in the heap. The garbage collector automatically deletes objects that are no longer needed.

2. Stack Memory
In Java, Stack memory is used to store local variables, method calls and references to an object. Each time a method is called, a new stack frame is created to hold local variables and object references. The stack memory is managed automatically, when a method finishes the stack frame is removed and the space used by its local variable is also released.

Note:

Primitive data types and local variables are stored in the stack.

3. Garbage Collector
In Java, The garbage collector is responsible for reclaiming memory by destroying objects that are no longer in use. When an object becomes unreachable that means no active reference points to it, it then becomes eligible for garbage collector. The garbage collector removes those objects freeing up the memory in the heap.

Types of Garbage Collectors:

Serial Garbage Collector: It is the simplest type of garbage collector. It uses a single thread to handle all garbage collection tasks.

Parallel Garbage Collector: It is the default garbage collector in Java 8. It uses multiple threads to perform garbage collection tasks.

Shenandoah Garbage Collector: It is another low-pause-time garbage collector introduced in Java 12.

Instance data: It refers to the actual fields or variables that belongs to an object.
Padding: It refers to the extra memory to align the object size to the word size for better performance.

GC-related Information: It is used by the garbage collector for managing the object lifecycle.

Q158: Object Lifecycle

In Java, it has seven states in Object lifecycle. They are,

Created
In use
Invisible
Unreachable
Collected
Finalized
De-allocated

The Seven States (as commonly described)
State	Meaning
Created	Memory is allocated and the constructor runs.
In use	The object has at least one strong reference and is actively used.
Invisible	The object is still reachable but not directly accessible via the current scope (e.g., it is held by a collection but the local variable has gone out of scope).
Unreachable	No strong references exist; the object is eligible for garbage collection.
Collected	The garbage collector has identified the object and reclaimed its memory (but before finalization).
Finalized	The finalize() method has been called (allows cleanup).
De‑allocated	Memory is fully freed and returned to the heap.


public class ObjectLifecycleDemo {

    // A simple class that lets us see when finalize() is called
    static class MyObject {
        private final int id;

        MyObject(int id) {
            this.id = id;
            System.out.println("[" + id + "] CREATED");
        }

        void use() {
            System.out.println("[" + id + "] IN USE – doing something");
        }

        @Override
        protected void finalize() throws Throwable {
            System.out.println("[" + id + "] FINALIZED (finalize() called)");
            super.finalize();
        }
    }

    public static void main(String[] args) throws InterruptedException {

        // ---------- 1. CREATED ----------
        MyObject obj = new MyObject(1);
        // The object is now in the "Created" state.

        // ---------- 2. IN USE ----------
        obj.use();                     // actively used
        System.out.println("State: IN USE\n");

        // ---------- 3. INVISIBLE ----------
        // Put the object into a collection, then remove the direct reference.
        // The object is still reachable (via the collection), but not directly
        // accessible through a local variable – this simulates "Invisible".
        java.util.ArrayList<MyObject> list = new java.util.ArrayList<>();
        list.add(obj);                // now list holds a reference
        obj = null;                   // direct reference gone – object is now "invisible"
        System.out.println("State: INVISIBLE (still in list, but no direct variable)\n");

        // Remove it from the list to make it truly unreachable.
        list.clear();                 // now no references at all

        // ---------- 4. UNREACHABLE ----------
        System.out.println("State: UNREACHABLE (no references remain)");

        // ---------- 5. COLLECTED & 6. FINALIZED & 7. DE‑ALLOCATED ----------
        // Suggest garbage collection. The JVM may collect it, call finalize(),
        // and finally de‑allocate the memory. We can observe finalization.
        System.gc();
        // Give GC a moment to run (not guaranteed, but for demonstration)
        Thread.sleep(500);

        System.out.println("\nAfter GC request – watch for finalize() output.");
        System.out.println("(The object is now COLLECTED, FINALIZED, and DE‑ALLOCATED)");
    }
}

Q161: MergeIntervalsStream

solving the merge intervals problem using streams in java

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class MergeIntervalsStream {
    public static int[][] merge(int[][] intervals) {
        if (intervals == null || intervals.length <= 1) {
            return intervals;
        }

        // 1. Stream, sort by start time, and accumulate via reduction
        List<int[]> mergedList = Arrays.stream(intervals)
                .sorted((a, b) -> Integer.compare(a[0], b[0]))
                .reduce(
                        new ArrayList<int[]>(),
                        (list, currentInterval) -> {
                            // If list is empty or no overlap, add current interval
                            if (list.isEmpty() || list.get(list.size() - 1)[1] < currentInterval[0]) {
                                list.add(currentInterval);
                            } else {
                                // Overlap found, merge by updating the end time of the last interval
                                list.get(list.size() - 1)[1] = Math.max(list.get(list.size() - 1)[1], currentInterval[1]);
                            }
                            return list;
                        },
                        (list1, list2) -> {
                            // Combiner for parallel streams (merges two pre-reduced lists)
                            if (list1.isEmpty()) return list2;
                            if (list2.isEmpty()) return list1;
                            
                            int[] lastOfFirst = list1.get(list1.size() - 1);
                            int[] firstOfSecond = list2.get(0);
                            
                            if (lastOfFirst[1] >= firstOfSecond[0]) {
                                lastOfFirst[1] = Math.max(lastOfFirst[1], firstOfSecond[1]);
                                list2.remove(0);
                            }
                            list1.addAll(list2);
                            return list1;
                        }
                );

        // 2. Convert the accumulated list back to a 2D array
        return mergedList.toArray(new int[mergedList.size()][]);
    }

    public static void main(String[] args) {
        int[][] intervals = {{1, 3}, {2, 6}, {8, 10}, {15, 18}};
        int[][] result = merge(intervals);
        
        System.out.println(Arrays.deepToString(result));
        // Output: [[1, 6], [8, 10], [15, 18]]
    }

Q162: Write a program in Java 8 streams to find the start and end indices of the second most frequently adjacent repeated character sequence in a given string. Input : aaabbbbbccdddddddee Output : Start Index: 3 End Index: 7

import java.util.AbstractMap;
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.regex.Matcher;
import java.util.regex.Pattern;
import java.util.stream.Collectors;
import java.util.stream.IntStream;

public class SecondFrequentSequence {
    public static void main(String[] args) {
        String input = "aaabbbbbccdddddddee";

        // Regex to match contiguous identical characters
        Matcher matcher = Pattern.compile("(.)\\1*").matcher(input);
        List<MatchResult> sequences = new ArrayList<>();

        while (matcher.find()) {
            sequences.add(new MatchResult(matcher.start(), matcher.end(), matcher.group()));
        }

        // Use Java 8 streams to find the distinct lengths in descending order
        List<Integer> distinctLengths = sequences.stream()
                .map(m -> m.length)
                .distinct()
                .sorted(Comparator.reverseOrder())
                .collect(Collectors.toList());

        // Ensure there is at least a second distinct sequence length
        if (distinctLengths.size() >= 2) {
            int secondMaxLength = distinctLengths.get(1);

            // Filter sequences matching the second max length and get the first occurrence
            sequences.stream()
                    .filter(m -> m.length == secondMaxLength)
                    .findFirst()
                    .ifPresent(result -> {
                        System.out.println("Start Index: " + result.start);
                        System.out.println("End Index: " + (result.end - 1));
                    });
        } else {
            System.out.println("No second most frequent adjacent sequence found.");
        }
    }

    // Helper class to hold sequence properties
    static class MatchResult {
        int start;
        int end;
        int length;

        MatchResult(int start, int end, String text) {
            this.start = start;
            this.end = end;
            this.length = text.length();
        }
    }
}


Explanation of the Logic:

Regex Tokenization: Pattern.compile("(.)\\1*") finds consecutive repeating character sequences like aaa, bbbbb, cc, etc.

Object Mapping: Each sequence is captured with its exact start index, exclusive end index, and length.

Stream Processing:.map(m -> m.length) extracts the lengths of the blocks..distinct() eliminates duplicate length values..sorted(Comparator.reverseOrder()) ranks lengths from longest to shortest.

Target Identification: We select the second item from our unique length list (distinctLengths.get(1)).

Index Extraction: We stream our original sequences again, filter for the target length, and extract the matching block. Note that result.end - 1 converts the regex exclusive end index into the standard inclusive end index requested by your example.

import java.util.*;
import java.util.stream.Collectors;

class Student {
    String name;
    int age;
    String department;
    List<Subject> subjects;
    double gpa;

    public Student(String name, int age, String department, List<Subject> subjects, double gpa) {
        this.name = name;
        this.age = age;
        this.department = department;
        this.subjects = subjects;
        this.gpa = gpa;
    }
}

class Subject {
    String name;
    int marks;

    public Subject(String name, int marks) {
        this.name = name;
        this.marks = marks;
    }
}

// Intermediate structure to tie a student's name to a specific subject score
record StudentSubjectScore(String studentName, String subjectName, int marks) {}

public class Main {
    public static void main(String[] args) {
        List<Student> students = List.of(
            new Student("Alice", 20, "CS", List.of(new Subject("Math", 85), new Subject("DSA", 90)), 8.5),
            new Student("Bob", 22, "CS", List.of(new Subject("Math", 60), new Subject("OS", 70)), 6.2),
            new Student("Charlie", 21, "ECE", List.of(new Subject("Signals", 55), new Subject("Math", 95)), 7.8),
            new Student("Diana", 23, "ECE", List.of(new Subject("Signals", 40), new Subject("Circuits", 30)), 4.1),
            new Student("Eve", 22, "ME", List.of(new Subject("Thermo", 88)), 9.0)
        );

        // 1. Flatten and group using Stream API
        Map<String, Optional<StudentSubjectScore>> highestMarksBySubject = students.stream()
            // Flatten the nested structure into individual record entries
            .flatMap(student -> student.subjects.stream()
                .map(subject -> new StudentSubjectScore(student.name, subject.name, subject.marks)))
            // Group by the subject name and find the maximum marks scored
            .collect(Collectors.groupingBy(
                StudentSubjectScore::subjectName,
                Collectors.maxBy(Comparator.comparingInt(StudentSubjectScore::marks))
            ));

        // 2. Display the formatted results
        highestMarksBySubject.forEach((subject, result) -> result.ifPresent(record -> 
            System.out.printf("Subject: %-10s | Student: %-10s | Highest Marks: %d%n", 
                subject, record.studentName(), record.marks())
        ));
    }
}

flatMap(): Converts a stream of Student objects (which contain nested lists of subjects) into a flat stream of custom mapping records (StudentSubjectScore)

Collectors.groupingBy(): Aggregates the data entries into subsets using the subjectName as the map key.

Collectors.maxBy(): Evaluates the records inside each grouped subject map bucket, keeping only the record containing the highest marks

record: A clean, lightweight Java feature used to temporarily bind the student's name, subject name, and score together during stream processing without modifying your source classes

In relational databases, an index will be applied to all three of these queries, provided that the appropriate indexes exist. The database engine's query optimizer evaluates the WHERE clauses to speed up data retrieval.

Queries 2 and 3: These will use a Single-Column Index. If you have an index on first_name, Query 2 will use it. If you have an index on last_name, Query 3 will use it.

Q:168: Association and Aggregation

                 Relationship
                     |
        ----------------------------
        |            |             |
    Association   Aggregation   Composition
	

Interview Answer (30-second version):

Association: A "uses-a" relationship where two objects interact but have independent lifecycles (e.g., Teacher and Student).

Aggregation: A weak "has-a" relationship where the parent references child objects, but the children can exist independently (e.g., Company and Employee).

Composition: A strong "has-a" relationship where the parent owns the child, and the child's lifecycle depends on the parent (e.g., Car and Engine, or Order and OrderItem).
Enterprise Spring Boot Examples

Association: OrderController → OrderService (controller uses the service).

Aggregation: Department → Employee (employees can belong to different departments over time).

Composition: Order → OrderItem (deleting an order removes its items, often implemented with JPA CascadeType.ALL and orphanRemoval = true).


---------------------

1. Association (Uses-A Relationship)
Definition

Association means one object knows about another object and uses it.

Neither object owns the other.

Both objects can exist independently.

Think of it as:

"A Teacher teaches Students."

If the teacher leaves,
students still exist.

If the students leave,
teacher still exists.

There is no dependency on lifecycle.

Real World Example
Teacher  ---------> Student

Teacher has students.

Student can exist without teacher.

Teacher can exist without student.

import java.util.stream.IntStream;

public class TransactionAnalyzer {

    public static int findMissingTransaction(int[] transactions) {
        int n = transactions.length + 1; // since one ID is missing from the sequence 1..n

        // Sum of 1..n using streams
        int expectedSum = IntStream.rangeClosed(1, n).sum();

        // Sum of actual elements in the array using streams
        int actualSum = IntStream.of(transactions).sum();

        return expectedSum - actualSum;
    }

    public static void main(String[] args) {
        int[] networkLog = {3, 1, 6, 2, 5};
        int missingId = findMissingTransaction(networkLog);
        System.out.println("Missing Transaction ID: " + missingId); // Should print 4
    }
}

How it works:

The array has n elements but represents a sequence of 1..n+1 with exactly one number missing.
IntStream.rangeClosed(1, n).sum() computes the expected sum of a complete sequence 1 to n (where n = transactions.length + 1).
IntStream.of(transactions).sum() computes the actual sum of the given array.
The difference between expected and actual sum gives the missing transaction ID.

Trace for {3, 1, 6, 2, 5}:

n = 5 + 1 = 6
expectedSum = 1+2+3+4+5+6 = 21
actualSum = 3+1+6+2+5 = 17
missing = 21 - 17 = 4 ✅

Note: This approach assumes the input is a permutation of 1..n+1 with exactly one number missing (as in your example). If the array could have duplicates, negative numbers, or an arbitrary range, a different approach (e.g., using boxed().collect(Collectors.toSet()) and comparing against a full range) would be needed — let me know if that's the case and I can adjust it
