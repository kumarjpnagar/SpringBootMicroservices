🔥 1. ENTITY & BASIC MAPPING
✅ What is JPA Entity?
A Java class mapped to a database table.

✅ Hands-on Example
import jakarta.persistence.*;

@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)

    @Column(name = "user_name", nullable = false)
    private String name;

    @Transient
    private String tempData; // not stored in DB

}

🔑 Key Annotations

@Table → table name

@Id → primary key

public List<User> dynamicSearch(EntityManager em) {

    CriteriaQuery<User> cq = cb.createQuery(User.class);

🚀 2. COMPLETE HANDS-ON EXAMPLE

✅ Step 1: Create Entity Class
package com.example.jpa.entity;

import jakarta.persistence.*;

@Entity  // 1️⃣ Marks this class as a JPA Entity
@Table(name = "users")  // 2️⃣ Maps to table name "users"
public class User {

    @Id  // 3️⃣ Primary Key
    @GeneratedValue(strategy = GenerationType.IDENTITY) // 4️⃣ Auto Increment
    private Long id;

    @Column(name = "user_name", nullable = false, length = 50) // 5️⃣ Column mapping
    private String name;

    @Column(unique = true)
    private String email;

    @Transient  // 6️⃣ Not stored in DB
    private String tempData;

    // Constructors
    public User() {}

    public User(String name, String email, String tempData) {
        this.name = name;
        this.email = email;
        this.tempData = tempData;
    }

    // Getters & Setters
}
🚀 3. EXPLANATION OF EACH ANNOTATION
🔶 1. @Entity
👉 Makes class a persistent entity

@Entity
✔ Hibernate will:

Create table (if not exists)

Track this object

❗ Without @Entity → Hibernate ignores the class

🔶 2. @Table
@Table(name = "users")
✔ Maps class → DB table

👉 If not used:

Class Name = Table Name (default)
User → user
🔶 3. @Id
@Id
private Long id;
✔ Defines Primary Key

❗ Mandatory for every entity

🔶 4. @GeneratedValue
@GeneratedValue(strategy = GenerationType.IDENTITY)
✔ Auto-generates ID

Strategies:
Strategy	Meaning
IDENTITY	Auto increment (MySQL)
SEQUENCE	DB sequence
TABLE	Table-based
AUTO	Hibernate decides
🔶 5. @Column
@Column(name = "user_name", nullable = false, length = 50)
✔ Customize column

Options:
Attribute	Meaning
name	Column name
nullable	NOT NULL
unique	Unique constraint
length	Column size
🔶 6. @Transient
@Transient
private String tempData;
✔ Not stored in DB

👉 Use when:

Temporary values

Calculations

API-only fields

🚀 4. DATABASE TABLE OUTPUT
Hibernate will generate:

CREATE TABLE users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_name VARCHAR(50) NOT NULL,
    email VARCHAR(255) UNIQUE
);
👉 tempData ❌ NOT present

Explain Object- Relation Mapping in Hibernate Hands On?

Great question — this is the core of Hibernate/JPA. I’ll explain Object-Relational Mapping (ORM) in a hands-on + practical + interview-ready way.

🚀 1. WHAT IS OBJECT-RELATIONAL MAPPING (ORM)?
👉 ORM = Mapping between:

Java Objects  ⇄  Relational Database Tables
Java (Object World)	DB (Relational World)
Class	Table
Object	Row
Field	Column
Reference	Foreign Key
🧠 WHY ORM?
Without ORM ❌ (JDBC way):

String sql = "INSERT INTO users (name) VALUES ('Rakesh')";
With ORM ✅ (Hibernate):

User user = new User();
user.setName("Rakesh");

entityManager.persist(user);
👉 Hibernate automatically generates SQL:

INSERT INTO users (name) VALUES ('Rakesh');

🧠 Concept

✅ Example
@Autowired
private EntityManager em;

public List<User> searchUsers(String name, Integer age) {

    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<User> cq = cb.createQuery(User.class);

    Root<User> root = cq.from(User.class);

    List<Predicate> predicates = new ArrayList<>();

    if (name != null) {
        predicates.add(cb.equal(root.get("name"), name));
    }

    if (age != null) {
        predicates.add(cb.greaterThan(root.get("age"), age));
    }

    cq.select(root).where(predicates.toArray(new Predicate[0]));

    return em.createQuery(cq).getResultList();
}

👉 Dynamic filters like:

Search API (optional filters)

    @JoinColumn(name = "user_id")
    private User user;
}
❌ Problem Code
public void fetchUsers() {

    List<User> users = userRepo.findAll(); // 1 query

    for (User user : users) {
        System.out.println(user.getOrders().size()); // N queries
    }
}

SELECT * FROM users;         -- 1 query

SELECT * FROM orders WHERE user_id = 3;
... (N times)
❌ Problem Impact
100 users → 101 queries ❌

✅ SOLUTION 1: FETCH JOIN (BEST)
✅ JPQL Fetch Join
@Query("SELECT u FROM User u JOIN FETCH u.orders")

🚀 2. LazyInitializationException
🧠 What is it?
👉 Happens when accessing LAZY data outside transaction

❌ Problem Code

    return userRepo.findAll(); // transaction ends
}
List<User> users = service.getUsers();

users.get(0).getOrders(); // ❌ Exception
❌ Error
LazyInitializationException:
could not initialize proxy - no Session
🧠 Why?
Session closed → Lazy data cannot load
✅ SOLUTIONS
✅ Solution 1: Use @Transactional
@Transactional
public List<User> getUsers() {

    List<User> users = userRepo.findAll();

    users.forEach(u -> u.getOrders().size()); // load inside tx

    return users;
}
✅ Solution 2: Fetch Join (BEST)
@Query("SELECT u FROM User u JOIN FETCH u.orders")
List<User> findAllWithOrders();
✅ Solution 3: DTO Projection (BEST PRACTICE)
@Query("SELECT new com.example.dto.UserDTO(u.name, o.product) " +
       "FROM User u JOIN u.orders o")

🚀 3. FETCH JOIN OPTIMIZATION
🧠 Why needed?
👉 Solve:

N+1 problem

Lazy loading issue

✅ Single Fetch Join
@Query("SELECT u FROM User u JOIN FETCH u.orders")
List<User> findAllWithOrders();
⚠️ Multiple Fetch Join Problem
@Query("SELECT u FROM User u JOIN FETCH u.orders JOIN FETCH u.roles")
👉 ❌ Cartesian product (data explosion)

✅ Solution: Use DISTINCT
@Query("SELECT DISTINCT u FROM User u JOIN FETCH u.orders")
List<User> findAllWithOrders();

🚀 1. ENTITY LIFECYCLE IN HIBERNATE
🧠 Definition
👉 Lifecycle = different states an entity goes through from creation to deletion

🔥 4 MAIN STATES
NEW (Transient) → MANAGED (Persistent) → DETACHED → REMOVED
🧭 DIAGRAM (VERY IMPORTANT)
        new User()
           │

           ▼
    🟢 MANAGED (PERSISTENT)
           │ detach() / session closed
           ▼
    🔵 DETACHED
           │ remove()
           ▼

🚀 3. HANDS-ON CODE FOR ALL STATES
✅ 1. TRANSIENT STATE
User user = new User();
user.setName("Rakesh");
🔍 Explanation
Not connected to DB

No ID generated

Not tracked by Hibernate

✅ 2. MANAGED (PERSISTENT STATE)
@Transactional
public void managedExample(EntityManager em) {

    User user = new User();
    user.setName("Rakesh");

    em.persist(user); // now MANAGED

    user.setName("Updated Name"); // auto-tracked
}
🔥 Important Behavior
👉 Hibernate automatically runs:

INSERT INTO user ...
UPDATE user SET name='Updated Name'
👉 No explicit save() needed

🧠 Why?
👉 Because of Persistence Context (dirty checking)

✅ 3. DETACHED STATE
@Transactional
public void detachedExample(EntityManager em) {

    User user = em.find(User.class, 1L); // managed

    em.detach(user); // now DETACHED

    user.setName("New Name"); // ❌ NOT saved
}
🔍 Explanation
Object exists

But not tracked anymore

Changes are NOT persisted

✅ 4. REMOVED STATE
@Transactional
public void removeExample(EntityManager em) {

    User user = em.find(User.class, 1L);

    em.remove(user); // marked for deletion
}
🔥 SQL
DELETE FROM user WHERE id=1;
🚀 4. PERSISTENCE CONTEXT (VERY IMPORTANT)
🧠 What is it?
👉 A cache inside Hibernate (EntityManager)

EntityManager = Persistence Context
🔥 Diagram

       ↓

       ↓
Database
🔑 Key Responsibilities
✔ Tracks entity changes

🚀 5. DIRTY CHECKING (MAGIC)
🧠 Concept
👉 Hibernate automatically detects changes

✅ Example
@Transactional
public void dirtyChecking(EntityManager em) {

    User user = em.find(User.class, 1L);

    user.setName("Updated Automatically");

    // No save() needed!
}
🔥 Hibernate does:
UPDATE user SET name='Updated Automatically' WHERE id=1;
🚀 6. MERGE (DETACHED → MANAGED)
🧠 Use case
👉 When working with detached objects

✅ Example
@Transactional
public void mergeExample(EntityManager em) {

    User detachedUser = new User();
    detachedUser.setId(1L);
    detachedUser.setName("Merged Name");

    User managedUser = em.merge(detachedUser);
}
🔍 Explanation
merge() returns managed copy

Original remains detached

🚀 7. FULL FLOW EXAMPLE
@Transactional
public void fullLifecycle(EntityManager em) {

    // 1. TRANSIENT
    User user = new User();
    user.setName("Rakesh");

    // 2. MANAGED
    em.persist(user);

    // 3. UPDATE (dirty checking)
    user.setName("Updated");

    // 4. DETACHED
    em.detach(user);

    // 5. Changes not saved
    user.setName("Not Saved");

    // 6. MERGE back
    em.merge(user);

    // 7. REMOVE
    em.remove(user);
}
