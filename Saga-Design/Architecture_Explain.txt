EHR Bridge / HL7 Messages / APIs to connect with hospital EMR/EHR systems

1. Backend Services (Java + Spring Boot)
Deployed to AWS ECS container (microservice)

Runs on port 8080

Includes:

REST APIs

HL7/PC message processors (for EHR integration)

Authentication via AWS Cognito + Okta SSO

Uses Redis (for caching sessions, tokens, quick lookups)

👉 Responsible for

Managing requests from UI

2. UI Layer
Can be Angular/React (mentioned: old UI and new UI both on port 4200)

Authenticated using SSO (Okta/AWS Cognito)

Talks to backend using REST APIs

3. Redis + H2
Redis: Cache layer for frequently accessed data like session info, provider schedules, tokens.

H2: Embedded database for local testing (not used in prod).

4. Database (PostgreSQL on AWS RDS)
Central database that stores:

Patient demographics

Provider templates

Appointments

Sync logs, etc.

All backend microservices read/write data here.

5. EHR/EMR Systems
These are external hospital systems, like:

Athena → API-based

NextGen → RPC-based

ECW (eClinicalWorks) → HL7/Third-party API

Allscripts → HL7 message–based

These systems communicate via the EHR Bridge.

6. EHR Bridge (Integration Layer)
Acts as a translator between your system and external EHRs.

Exposes a REST API or HL7 Interface.

Handles inbound/outbound messages:

HL7 ADT (Admit/Discharge/Transfer)

HL7 SIU (Scheduling)

HL7 ORU (Observation Results)

7. Batch Jobs (Cron Jobs)
Runs on a scheduled basis.

Responsible for data synchronization between your system and EHRs.

Types:

Patient Sync: updates patient info from EHR.

Provider Template Sync: syncs clinical templates.

Inventory Sync: syncs availability & appointments.

⚙️ 3️⃣ Data Flow (Sequence Example)
Let’s take an example of creating a new patient appointment from your system to the EHR.

🩺 Example: Appointment Sync Flow
Step 1: UI Request
A receptionist uses the web UI (Angular app).

Enters patient info and books an appointment.

Frontend (Angular) → Backend API (Spring Boot)
POST /appointments
Step 2: Backend Processes Request
Spring Boot app validates data, stores appointment record in PostgreSQL.

Also pushes an HL7 SIU message to the EHR Bridge or calls its API.

HL7 SIU^S12 (New Appointment)
Step 3: EHR Bridge Translates Message
Converts HL7 message into the format expected by the target EHR.

Sends it to Athena/ECW/NextGen depending on configuration.

Step 4: EHR Updates External System
The EHR receives the new appointment.

Responds with a confirmation or an updated identifier (e.g., external appointment ID).

Step 5: Backend Updates Database
Backend receives confirmation from EHR Bridge.

Updates appointment record in PostgreSQL with the EHR’s external ID.

Step 6: Batch Jobs Run (Nightly Sync)
A cron-based batch job checks for discrepancies between systems.

Runs Inventory Sync to update availability.

Runs Patient Sync for any new EHR patients not yet in your system.

🔄 Step 5 — Rolling Update (Zero Downtime)
Update image version:

kubectl set image deployment/order-service \
order-container=username/order-service:v2
Kubernetes will:

Start new pod

Wait for readiness

Gradually shift traffic

Stop old pod

Check rollout:

kubectl rollout status deployment/order-service
Rollback if needed:

kubectl rollout undo deployment/order-service
📈 Step 6 — Auto Scaling
Enable HPA (Horizontal Pod Autoscaler):

kubectl autoscale deployment order-service \
--cpu-percent=70 \
--min=2 \
--max=10
Now:

If CPU > 70% → Kubernetes increases pods automatically.

Check:

kubectl get hpa
