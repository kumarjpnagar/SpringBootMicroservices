5️⃣ Propagation Types (Very Important)
Defines how transactions behave when one method calls another.

1️⃣ REQUIRED (Default)
Use existing transaction
or create new
Example:

A() -> B()
If A has transaction → B joins it.

2️⃣ REQUIRES_NEW
Always creates new transaction

A() -> B()
B runs in separate transaction

Example:

@Transactional(propagation = Propagation.REQUIRES_NEW)
Use case:

Audit logs.

3️⃣ SUPPORTS
Run with transaction if exists
Otherwise run without transaction
4️⃣ NOT_SUPPORTED
Run without transaction

5️⃣ MANDATORY
Must run inside existing transaction.

6️⃣ NEVER
Fails if transaction exists.

7️⃣ NESTED
Creates nested transaction with savepoints.

6️⃣ Isolation Levels
Controls concurrent transaction visibility

Isolation Level	Problem Prevented
READ_UNCOMMITTED	nothing
READ_COMMITTED	Dirty read
REPEATABLE_READ	Non-repeatable read
SERIALIZABLE	Phantom read
Example

@Transactional(isolation = Isolation.SERIALIZABLE)

7️⃣ Transaction Rollback Rules

✔ Rollback on RuntimeException

3️⃣ Step-by-Step Internal Flow

Step 1 — Client Calls Service

orderService.placeOrder();
But actually:

Proxy.placeOrder()
Spring injects proxy instead of real bean.

Step 2 — Proxy Intercepts Method
Proxy checks:

Is method annotated with @Transactional?
If yes → invoke TransactionInterceptor

Step 3 — TransactionInterceptor Starts Transaction
TransactionInterceptor internally calls:

PlatformTransactionManager.getTransaction()
Example:

JpaTransactionManager
or
DataSourceTransactionManager
This does:

1 Get DB connection
2 Disable auto commit
3 Start transaction

Step 4 — Execute Business Logic
Now actual method executes:

public void placeOrder() {

    orderRepository.save(order);

    paymentService.processPayment();
}

Step 5 — Commit or Rollback
If success:

transactionManager.commit()
If exception:

transactionManager.rollback()

7️⃣ Internal Classes Used by Spring
Main internal classes:

PlatformTransactionManager	Commit/rollback
TransactionStatus	Current transaction status
Internal code (simplified):

public Object invoke(MethodInvocation invocation) {

    TransactionStatus status =
        transactionManager.getTransaction(definition);

    try {

        Object result = invocation.proceed();

        transactionManager.commit(status);

        return result;

    } catch (Exception ex) {

        transactionManager.rollback(status);

        throw ex;
    }
}

5️⃣ Service Example (Propagation REQUIRED)
REQUIRED = Join existing transaction or create new

@Service
public class OrderService {

    @Autowired
    OrderRepository repository;

    @Autowired
    AuditService auditService;

    @Transactional(propagation = Propagation.REQUIRED)
    public void createOrder() {

        OrderEntity order = new OrderEntity();
        order.setProduct("Laptop");

        repository.save(order);

        auditService.auditLog();

        throw new RuntimeException("Order failure");
    }
}

6️⃣ Service with REQUIRES_NEW
REQUIRES_NEW = Always create new transaction

@Service
public class AuditService {

    @Autowired
    OrderRepository repository;

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void auditLog() {

        OrderEntity audit = new OrderEntity();
        audit.setProduct("AUDIT_LOG");

        repository.save(audit);
    }
}

Which propagation support partial rollback transactyion?

The propagation that supports partial rollback in Spring transactions is:

✅ Propagation.NESTED
NESTED allows partial rollback using database savepoints.

That means:

Parent transaction continues

Only the nested part rolls back

1️⃣ Concept of Partial Rollback
Example scenario:

Place Order
   |
   |-- Save Order
   |-- Process Payment
   |-- Send Notification
If notification fails, we may want:

✔ Order saved
✔ Payment completed

❌ Notification rolled back
This is partial rollback.

2️⃣ How NESTED Works Internally
NESTED creates a savepoint inside the parent transaction.

Main Transaction
      |
      |--- Savepoint
              |
              |--- Nested Transaction
If nested fails:

Rollback to savepoint
Parent transaction continues

@Service
public class SagaOrchestrator {

    @Autowired
    OrderService orderService;

    @Autowired
    PaymentService paymentService;

    @Autowired
    InventoryService inventoryService;

    @Autowired
    NotificationService notificationService;

    public void executeSaga() {

        Order order = orderService.createOrder();

        try {

            paymentService.processPayment(order.getId());

            inventoryService.reserveInventory(order.getProduct());

            notificationService.sendNotification();

            System.out.println("Order Completed");

        } catch(Exception e) {

            System.out.println("Saga failed. Running compensation");

            orderService.cancelOrder(order.getId());
        }
    }
}

1️⃣ What is Transaction Isolation
Isolation defines how transactions interact with each other when running concurrently.

Example:

User A updates account balance
User B reads account balance
Isolation level controls what User B sees.

2️⃣ Common Concurrency Problems
1️⃣ Dirty Read
Transaction reads uncommitted data.

Example:

Tx1 updates balance = 1000
Tx2 reads balance = 1000
Tx1 rollback
Tx2 read invalid data.

2️⃣ Non-Repeatable Read
Same row read twice gives different values.

Example:

Tx1 reads price = 100
Tx2 updates price = 200
Tx1 reads again = 200

3️⃣ Phantom Read
New rows appear during transaction.

Example:

Tx1: SELECT * FROM orders WHERE price > 100
Tx2 inserts new order
Tx1 runs query again → new row appears

3️⃣ Spring Isolation Levels
Spring uses:

org.springframework.transaction.annotation.Isolation
Levels:

Isolation Level	Prevents
READ_UNCOMMITTED	Nothing
READ_COMMITTED	Dirty Read
REPEATABLE_READ	Dirty + Non-repeatable
SERIALIZABLE	All problems

9️⃣ REPEATABLE_READ Example

Dirty reads
Non-repeatable reads

@Transactional(isolation = Isolation.REPEATABLE_READ)

    // another transaction updates record

    System.out.println(acc1.getBalance());
    System.out.println(acc2.getBalance());
}
Result:

Both values remain same
