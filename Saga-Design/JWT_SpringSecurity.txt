1️⃣ What is JWT (JSON Web Token)
JWT is a secure token used for stateless authentication.

Instead of storing sessions on the server, the server generates a token and the client sends it in every request.

Structure of JWT:

xxxxx.yyyyy.zzzzz
Part	Description
Header	Algorithm & token type
Payload	User data (username, role etc)
Signature	Security verification
Example Payload

{
 "sub": "rakesh",
 "iat": 1710000000,
 "exp": 1710003600
}

8️⃣ CustomUserDetailsService
Spring Security loads user from DB.

@Service
public class CustomUserDetailsService implements UserDetailsService {

    @Autowired
    private UserRepository repository;

    @Override
    public UserDetails loadUserByUsername(String username)
            throws UsernameNotFoundException {

        User user = repository.findByUsername(username)
                .orElseThrow(() -> new UsernameNotFoundException("User not found"));

        return new org.springframework.security.core.userdetails.User(
                user.getUsername(),
                user.getPassword(),
                List.of(new SimpleGrantedAuthority(user.getRole()))
        );
    }
}

9️⃣ JWT Utility Class
Responsible for:

create token

validate token

extract username

@Component
public class JwtUtil {

    private final String SECRET = "mysecretkey";

    public String generateToken(String username) {

        return Jwts.builder()
                .setSubject(username)
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + 1000*60*60))
                .signWith(Keys.hmacShaKeyFor(SECRET.getBytes()))
                .compact();
    }

    public String extractUsername(String token) {

        return Jwts.parserBuilder()
                .setSigningKey(SECRET.getBytes())
                .build()
                .parseClaimsJws(token)
                .getBody()
                .getSubject();
    }

    public boolean validateToken(String token, String username) {

        return extractUsername(token).equals(username);
    }
}

🔟 JWT Authentication Filter
This filter checks token for every request.

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Autowired
    private JwtUtil jwtUtil;

    @Autowired
    private CustomUserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain)
            throws ServletException, IOException {

        String header = request.getHeader("Authorization");

        String token = null;
        String username = null;

        if (header != null && header.startsWith("Bearer ")) {

            token = header.substring(7);
            username = jwtUtil.extractUsername(token);
        }

        if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {

            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            if (jwtUtil.validateToken(token, userDetails.getUsername())) {

                UsernamePasswordAuthenticationToken authToken =
                        new UsernamePasswordAuthenticationToken(
                                userDetails,
                                null,
                                userDetails.getAuthorities());

                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }

        filterChain.doFilter(request, response);
    }
}

1️⃣1️⃣ Security Configuration
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Autowired
    private JwtAuthenticationFilter filter;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {

        http
            .csrf().disable()
            .authorizeHttpRequests()
            .requestMatchers("/auth/login").permitAll()
            .anyRequest().authenticated()
            .and()
            .addFilterBefore(filter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

}

1️⃣2️⃣ Authentication Controller
Login API generates JWT.

@RestController
@RequestMapping("/auth")
public class AuthController {

    @Autowired
    private AuthenticationManager authenticationManager;

    @Autowired
    private JwtUtil jwtUtil;

    @PostMapping("/login")
    public String login(@RequestBody AuthRequest request) {

        Authentication authentication =
                authenticationManager.authenticate(
                        new UsernamePasswordAuthenticationToken(
                                request.getUsername(),
                                request.getPassword()));

        if(authentication.isAuthenticated()) {

            return jwtUtil.generateToken(request.getUsername());
        }

        throw new RuntimeException("Invalid credentials");
    }
}

1️⃣ Problem with Distributed Transactions
In microservices, each service has its own database (Database per Service pattern).

Example:

Order Service  -> Order DB
Payment Service -> Payment DB
Inventory Service -> Inventory DB
Suppose we execute this flow:

Create Order
 ↓
Process Payment
 ↓
Reserve Inventory

If Inventory fails, we must undo previous steps.

Traditional ACID transaction cannot span multiple services.

So we use SAGA Pattern.

2️⃣ What is SAGA Pattern
A Saga is a sequence of local transactions.

If one step fails → compensating transaction is executed to undo previous steps.

Example:

1 Create Order
2 Process Payment
3 Reserve Inventory

If step 3 fails:

Compensation:
Cancel Payment
Cancel Order
This is called Partial Rollback.

3️⃣ Types of Saga

1️⃣ Choreography Saga
Services communicate via events (Kafka).

OrderCreated → PaymentService
PaymentSuccess → InventoryService
InventoryFailed → PaymentRollback → OrderRollback

2️⃣ Orchestration Saga
A Saga Orchestrator controls the flow.

Saga Orchestrator
     |
     |--> Order Service
     |--> Payment Service
     |--> Inventory Service
	 
If failure occurs → orchestrator triggers compensation.

@Service
public class OrderService {

    @Autowired
    OrderRepository repository;

    @Transactional
    public Order createOrder(Order order){

        order.setStatus("CREATED");

        return repository.save(order);
    }

    @Transactional
    public void cancelOrder(Long orderId){

        Order order = repository.findById(orderId).get();

        repository.save(order);
    }
}

9️⃣ Saga Orchestrator
Central service controlling transaction.

@Service
public class OrderSagaService {

    @Autowired
    OrderService orderService;

    @Autowired
    PaymentService paymentService;

    @Autowired
    InventoryService inventoryService;

    public void placeOrder(Order order){

        Order createdOrder = orderService.createOrder(order);

        try{

            paymentService.processPayment(
                    new Payment(createdOrder.getId()));

            inventoryService.reserveInventory(
                    order.getProductId());

        }
        catch(Exception e){

            paymentService.refundPayment(createdOrder.getId());

            orderService.cancelOrder(createdOrder.getId());

            throw new RuntimeException("Saga Rollback Completed");
        }

    }

}
This is partial rollback using compensating transactions.

2️⃣ Why @Transactional Alone Cannot Solve It
@Transactional only works within a single database transaction.

Example:

@Transactional
public void updateUser(){
   updateUserTable();
   callNotificationService();
}
Problem:

User DB -> COMMITTED
Notification -> SUCCESS
Audit -> FAILED
Now system is inconsistent.

We need SAGA compensation.

3️⃣ Saga Strategy for Update Rollback
When performing update operations, we store previous state.

So rollback can restore old data.

Step 1: Save OLD USER STATE
Step 2: Update User
Step 3: Update Notification
Step 4: Update Audit

If step 4 fails:

Compensation
↓
Restore Notification
↓
Restore User

🔟 Saga Orchestrator (Main Logic)
@Service
public class UserSagaService {

    @Autowired
    private UserService userService;

    @Autowired
    private NotificationService notificationService;

    @Autowired
    private AuditService auditService;

    public void updateUserSaga(Long id,String name,String email){

        User oldUser = userService.getUser(id);

        try {

            userService.updateUser(id,name,email);

            notificationService.updateNotification(id);

            auditService.updateAudit(id);

        }
        catch(Exception ex){

            // compensation transactions

            notificationService.rollbackNotification(id);

            userService.restoreUser(oldUser);

            throw new RuntimeException("Saga rollback executed");

        }

    }
}

1️⃣5️⃣ Interview Answer
If interviewer asks:

How do you implement partial rollback for update operations?

Answer:

For update operations in distributed microservices we use Saga Pattern.

Before updating, we capture the previous state of the entity.

If a downstream service fails, compensating transactions restore the previous state.

Spring @Transactional guarantees atomicity within each service, while Saga ensures eventual consistency across services.
